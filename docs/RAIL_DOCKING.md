# 铁路对接连接器

版本：0.1.51 · 可选依赖：Create Simulated 1.3.2（本机由 Aeronautics 1.3.2 整合包提供）

## 使用步骤

0.1.50 在客户端预先拦截选择连接器后的车站右击，避免原版车站界面先行打开；绑定校验和数据修改仍只在服务端执行。连接器本体与伸出的对接头均支持选择和查看，普通扳手右击用于选择绑定，潜行扳手右击保留原生拆卸

1. 在本模组创造物品栏取出“铁路对接连接器”，车载端与世界端各安装一个。生存合成使用原生对接连接器与机械动力列车机壳
2. 像原版一样把邮箱关联到车站，并设置邮箱地址。放在车站附近不等于关联；铁路连接器不自行寻找附近邮箱
3. 手持扳手右击世界端铁路连接器，然后用扳手右击目标车站完成绑定。再次用扳手选择连接器并右击同一站可解除绑定，点击另一站则重新绑定。选择有效期 30 秒，连接器与车站距离最多 64 格，不能跨维度
4. 空手右击铁路连接器查看车站、邮箱地址、车载编组与对接状态；工程师护目镜也显示这些信息。地址来源是车站实时关联邮箱，不需要在连接器里再次填写
5. 调整两端朝向和间距，使列车在原有自动停车点停稳时可以按原生规则对接。平台高度改动的旧车先重新上轨；本功能不改变原生对接距离、角度容差，也不把车体强行传送到连接器前
6. 插入取件/派送时刻表。自动停站时铁路款两端申请伸出与锁定，确认互相配对、两端锁定且车载端属于本列车后才交换包裹
7. 装卸与时刻表等待条件完成后，释放本列车申请的锁定，等待原生对接约束解除再发车。外部红石供电仍有效；若用持续供电强制锁定，需要自行解除该供电

原生扳手选择与潜行扳手拆除功能保留，绑定使用空手操作，不占用扳手。普通原生连接器继续维持原行为；铁路自动装卸需要两端都使用铁路款。

## 实现与数据边界

新方块和方块实体直接继承原生 `DockingConnectorBlock` / `DockingConnectorBlockEntity`。原生 NBT 仍由父类保存/恢复，包括缓冲与对接状态；不克隆第二套库存、配对 ID 或物理关节。模型、纹理、动画、声音、配对与锁定过程沿用原生实现。注册对应的物品、流体、电能能力；ComputerCraft 存在时通过 Simulated 的服务登记原生有线网络端点，未重新实现其网络。

复用原生伸出头方块，并仅扩展其底座识别，让原生头也认可铁路款底座。破坏伸出头仍沿用原生处理，不生成第二个连接器掉落。物理质量与体积采用锁定版本原生连接器的属性，新版平台高度没有在此再次调整。

铁路附加持久数据只有绑定车站 UUID 与方块位置。世界侧索引使用 SavedData 保存端点位置，卸载端点不会被当作不存在的车站；不会为了索引加载新区块。车载编组每次从实际车体与车钩连接读取，同车体多转向架不重复计算，无转向架拖车包含在内。

界面用的车名、地址和编组数量是服务器刷新后发给客户端的显示快照，约每秒更新一次，不作为寻路或包裹分流的权威数据。绑定车站被删除/替换后需要重新绑定；不按同名自动接管另一站。

自动锁定请求是短期运行状态，不保存到存档。心跳 40 tick 过期，完成、暂停、手动接管时主动释放，释放后留 20 tick 供原生机构解除。另一列车不能续期或释放当前列车的请求；车体移动、退出重进后不会继承一个永久自动锁。原生手动红石锁不被覆盖。

包裹层在有效对接期间，把整列可写库存与已绑定车站的原版邮箱作为一次逻辑交换。包裹不强制逐个经过原生单槽缓冲，实际物品仍通过唯一的 `ParcelTransfer` 路径搬运；0.1.46 的无对接直接交换已经加上同一门控，不与新路径并行。地址筛选仍使用原版 `PackageItem.matchAddress`。

普通物品、流体和电能保留原生缓冲与管线输送方式，未实现对任意车载箱子、水箱的自动抽取/分配；整列访问在本轮用于包裹任务和既有货物统计。只读或不可修改的车载存储边界沿用 `PACKAGE_COMPATIBILITY.md`。

有邮箱但没有绑定铁路端点的普通目的站不直接交换邮件，也不阻止普通列车按其条件离站。取件/派送选站只考虑绑定了铁路连接器的站点；有效绑定但端点未加载或未成功锁定时等待，配对到另一列车时不得交换。

Simulated 未安装时不注册新方块、方块实体或客户端渲染器，条件合成配方不生效，包裹取派指令在装表时报告缺少支持。基础转向架、手动驾驶和其他已有时刻表能力保留。本轮 API 编译可从本机原始 Aeronautics 整合包提取内嵌 Simulated，只作 compileOnly 使用，不重新打包或在运行目录安装重复副本；其他开发环境可用 `-Psimulated_api_jar=<Simulated 发布 jar>`，没有本地发布包时构建脚本尝试对应 Maven 坐标。

## 客户端测试场景

1. 世界端绑定 A 站，A 关联两个邮箱，空手与护目镜查看站名/地址；修改邮箱地址、站名、关联关系后检查显示与实际路由同步。重新绑定、解除绑定、超时选择与权限检查不应打开错误界面或破坏方块
2. A/B 各绑定铁路世界端，列车安装铁路车载端与箱子，测试取件 B → 延时或装卸空闲 → 派送；到站前不能远程搬包裹，停稳且锁定后才交换，完成后应解锁发车
3. 包裹分别装在主车和连挂拖车中，同车体装多副转向架，检查整列取派与总数守恒；旁边另一列车或另一个站的端点不能参与此次交换
4. 接口错向、距离不合、只安装原生车载端、一端被其他列车占用时应等待。修正位置后继续，不能无接触直接完成装卸
5. 满仓后恢复、重复停站、同站多邮箱、持续邮件输入与空闲计时，确认只有一次实际转移，没有重新装回本站已送达邮件
6. 手动红石锁与自动锁分别测试：自动任务完成、暂停、取回时刻表、手动接管、拆除主控后不能永久维持自动锁；外部持续供电时不得强行发车
7. 对接等待、满仓等待、正常装卸后分别退出重进，检查绑定、原生缓冲和时刻表进度保持。端点或拖车延迟加载时不误判为空；移动/粘合车载端后不得残留世界站点索引
8. 六个朝向、伸缩模型、选框与碰撞、破坏伸出头、生存/创造拆除、扳手选择与潜行扳手拆除。工程师护目镜与中英文缩放下提示不应泄露翻译键
9. 原生物品/流体/电能输送、原生连接器与铁路款之间的普通对接、ComputerCraft 有线连接及已有 Hose / Automated Logistics 兼容回归；不将包裹铁路适配视为其他模组自动驾驶也已适配
10. 分别在安装/不安装 Simulated 的环境启动，检查可选类加载、条件配方、渲染器、伸出头 Mixin 与物理属性资源。日志关注 `[RailDock]`、`[PackageMail]`、`[AutomaticTrain]`、Mixin 和库存/存档异常

## 已执行检查

完整离线构建与语言检查；`RailDockCheck` 覆盖所有权、续期、过期、释放、冷却、外站/外列车拒绝、拖车、双端锁定与资源状态覆盖。发布包接口签名检查已包含伸出头补丁所需的两个方法，共 38 项；该检查不能证明 Mixin 已实际应用。

本轮未打开客户端或自行开启服务器。实际伸缩配对、铁路停车与原生物理关节相互作用、ComputerCraft 以及完整退出重进流程仍待上述客户端验收。
