# 自动驾驶选岔修复

版本：0.1.48

## 现象与依据

用户反馈：时刻表自动运行时偶尔走错分支，随后退出自动状态。0.1.47 测试日志中，在驶向 111 站的过程中出现运行状态 3 转状态 7，并施加制动；稍后继续时路线距离明显变长。旧日志没有记录具体岔路出口，因此不能单凭这些日志确认每次错误的唯一原因。

源码发现以下错误入口，已针对修正：

1. 自动导航通过 `nearest` 重新寻找头轴附近轨段，可能把岔路旁更近的邻接分支当作实际所在轨道，与物理导向选定的轨段不一致。现在依据轮轴导向样本，只在其真实轨段上刷新位置；仅尚无导向样本的初始定位可搜索最近轨道
2. 导航进度原来只检查当前、下一段及前一段。一个服务端 tick 跨过多个短轨段时会误报偏离，现在允许沿剩余计划向前定位，并明确核对行驶方向
3. 选岔会先写入编组历史，再验证候选轨段是否能承接轮轴。候选投影失败也可能留下出口锁。现在分为无副作用的预选与成功切入后的提交，未加载或投影失败不提交
4. 已整列通过的旧历史可能把新的自动行程当成倒车回溯。现在头轴可按计划建立新通过记录；尚有车轴跨在岔路上的通行记录继续保留，后轴/后车不能换支，手动倒车仍沿原路回溯
5. 自动计划缺少当前岔路出口时，原先直接退回默认角度选路。现在不任取其他出口，发出重算请求并制动；信号停车、等待规划等期间保留自动导航身份，不退回手动默认选岔

路线不匹配但轮轴仍有有效轨道导向时，保持时刻表运行并重新规划，而不是立即暂停。真正离轨、轨道缺失、编组变化、紧急制动等原有暂停条件不被取消。

重算期间仅在原有采样距离与已加载区块范围内短暂保留前一个合法导向样本，不将此作为无限延长轨道或保证任意速度都能停车的手段。没有修改轮轨受力、平台高度或列车最高速度。

## 诊断日志

- `[AutomaticJunction]`：头轴实际提交的岔路记录，包含车体/轮轴、节点、来向、计划出口、实际出口和目标站
- `[AutomaticJunctionRetry]`：计划出口缺失或不在可用候选中，记录候选出口并请求重算
- `[AutomaticRouteMismatch]`：真实导向轨段与导航进度不匹配，记录实际边、计划边与进度，保持运行并重算

## 客户端测试清单

1. 同一个 Y 形岔路，分别将目标站放在较直和较弯的分支，双向重复通过；自动驾驶必须按目标站选岔
2. 使用有两个以上转向架的同一车体及两节连挂车，确认全部轮轴走同一分支，没有头车正确、后车换支
3. 循环时刻表多次经过同一岔路，并改变目的站；整列已通过后的旧记录不能强迫新行程重复旧出口
4. 在岔路前暂停/继续、手动接管后恢复自动、红灯停车后放行以及装卸锁解除后发车，确认自动计划没有变成默认选路
5. 连续短轨段、高速驶过邻接岔路、站点邻近岔路时，不因一次跨越多段而退出自动；出现重算时检查新增日志是否对应有效出口
6. 手动 A/D、无输入优先小转角、车尾跟随、半列跨岔路时倒车，保持原有行为；拆掉计划分支后应停车等待/重算，不悄悄驶入另一支

自动检查扩展 `ConsistRouteCheck` 和 `AutomaticScheduleCheck`，覆盖预选不污染、接受后提交、后轴一致性、历史与新计划、未整列通过时的倒车锁、多个短段进度、反向边拒绝及计划出口查询。已运行完整离线构建。此轮未重启客户端，实际岔路修复效果待以上场景验收。
