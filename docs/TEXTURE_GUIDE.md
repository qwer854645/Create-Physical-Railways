# Minecraft 贴图规范

本文件描述 Minecraft 方块贴图的固有约束，以及本项目在 Create 材质体系内自绘材质时的做法。它回答的是“为什么这样画”，不是“照抄某个样子”。新增或修改任何方块、物品、界面贴图前先读本文件，并与 `PROJECT_STYLE.md`、`project-style.json` 一起使用：前者管文案与界面，本文件管像素。

## 一、约束从哪来

| 约束 | 具体事实 | 对画法的要求 |
|---|---|---|
| 分辨率 | 方块贴图默认 16×16，Create 与本项目也以 16×16 为主 | 一块贴图内只有 256 个像素，容不下三种材质 |
| **最终像素密度** | 贴图最终被采样到模型面的**屏幕尺寸**上：一块 5/16 格的板在常见视距下约占 **13×13 屏幕像素** | **按屏幕上的实际像素数设计。模型格数不等于屏幕像素数**（此处曾写错：5/16 格并不等于 5 像素） |
| 特征尺寸 | 缩到 13 像素后，1 纹理像素的特征会被平均掉，2~3 纹理像素的特征约剩 1 屏幕像素 | 主体特征要占画面的 1/4 以上，细节点缀不小于 2 纹理像素 |
| 面方向着色 | 原版对面做固定明度：顶 100%、南北 80%、东西 60%、底 50% | 不要在贴图里再烘焙一层大方向光，否则顶面会过曝、底面死黑 |
| Mipmap | 默认 4 级，远处贴图被逐级缩小 | 单像素噪点在 mipmap 下会糊成脏灰；细节至少要 2×2 才保得住 |
| 无抗锯齿 | 像素是硬边，没有半透明过渡 | 所有形状必须是整数像素，斜线用阶梯，不用灰阶描边软化 |
| 平铺 | 同类方块并排时贴图首尾相接 | 左右、上下边缘要能对上；边缘留出“安静区” |
| 光照系统 | 游戏会乘以方块光照与天空光，暗部会再暗一次 | 贴图自身的中位数不要压得太黑，否则井下全黑 |

## 二、调色板

- 一块 16×16 贴图 **8～16 色**，单一材质控制在 **3～4 级明度**
- 不用纯黑 `#000000` 与纯白 `#FFFFFF`；最深色带一点冷色（偏蓝紫），最亮色带一点暖色（偏黄橙）
- 亮部偏暖、暗部偏冷，这就是常见“手绘感”的来源；只做明度阶梯会显得塑料
- 同一材质在整套资源里用同一组色，不要每块重新调

## 三、明度结构

顺序是**剪影 → 明度 → 色相**。远看只认得出明暗块，所以：

1. 先保证去掉颜色、只看明度时，形体仍然清楚
2. 焦点区（不超过画面的 1/4）用最高对比，其余压低
3. 材质的“厚度”靠 1 像素的亮边 + 1 像素的暗边表达，不靠渐变

## 四、像素级手法

- **倒角**：受光边亮 1 像素、背光边暗 1 像素，是最省像素的立体感
- **铆钉 / 螺栓**：2×2 像素，左上亮右下暗；成阵列时用固定间距
- **凹槽**：上边暗、下边亮（反向着色的凹），与凸起的画法相反
- **纹理**：用 2×2 或 3×3 的簇，不用单像素随机噪点
- **发光体**（灯、屏幕、指针）：接近黑的底色 + 少量高亮像素，周围留 1 像素暗边来衬亮

## 五、材质识别速查

| 材质 | 明度 | 特征 |
|---|---|---|
| 工业铁 / 铁板 | 中灰，冷阴影 | 板缝、铆钉列、亮顶边 |
| 黄铜 | 暖中等，最高不超过浅黄 | 亮顶边 + 角落氧化变暗 |
| 暗金属 | 低明度但要留层次 | 只靠亮边区分结构，不靠纹理 |
| 木材 | 暖褐，明度跨度小 | 顺纹 1 像素细线、端面年轮 |
| 玻璃 / 屏幕 | 近黑 | 少量亮斑 + 一条反光斜线 |
| 橡胶 / 皮 | 低明度，几乎无高光 | 圆角、无锐边 |

## 六、与 Create 的一致性

- **优先引用 Create 的贴图**：`create:block/industrial_iron_block`、`brass_block`、`dark_metal_block`、`gauge`。引用时不改色，位置对了就自然统一
- 只有上游没有对应材质时才自绘，并把自绘材质集中登记，避免散落
- 黄铜高光取 `PROJECT_STYLE` 的 `ACCENT`（`#E4B763`）一族；界面深底取 `RECESS`（`#303030`）一族
- 引用 Create 纹理时注意**裁剪**：它的贴图是给整格用的，压到小面上会糊，见下条

## 七、反面案例（本项目真实发生过）

- 驾驶台“屏幕”是一块 5/16 格的板（约 13 屏幕像素），原来直接贴整张 `create:block/gauge`（16×16 表盘）并映射 `uv [0,0,16,16]`：整块表盘连同它的指针、刻度一起被压进 13 像素，只剩一团糊斑
- 第一次修正**修错了方向**：把它当成“只有 5 个像素”，于是用 5×5 的逻辑格重画，结果特征过少、显得简陋（玩家反馈“太简陋”）。真正的约束是**屏幕像素数（约 13）**，而不是模型格数
- 正确做法是**按 13 像素的可用量设计**：16×16 贴图可以使用，但主体特征要占足够大比例（例如黄铜边框 1 像素、三颗 2×2 指示灯、两行 2~3 像素高的读数），细节不必压缩到 1 像素
- 同理，引用 Create 大贴图时若目标面很小，应改用 `uv` 裁剪出局部，而不是整体压缩

## 八、自检清单

提交任何贴图前逐条过：

- [ ] 缩放到**最终面尺寸**后仍能认出这是什么
- [ ] 去掉颜色只看明度，是否仍有层次
- [ ] 2×2 平铺后是否出现明显重复纹样
- [ ] mipmap 4 级后是否糊成一团（把图缩到 1/16 看）
- [ ] 是否只有 8～16 色、单材质不超过 4 级明度
- [ ] 是否与相邻方块并排同一套色温
- [ ] 是否重复烘焙了方向光（顶面过亮、底面死黑）
- [ ] 是否引用了可用的 Create 原版材质而没有自造
- [ ] 贴图文件名与模型引用一致，路径在 `assets/guidedrailways/textures/block/` 下
