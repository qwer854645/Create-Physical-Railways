# 内置物理体跨维度传送

2026-11-02：已接入原版下界传送门自动触发，尚未完成游戏内迁移验收。直接使用当前 Sable 2.0.6 API，不依赖或复制第三方传送模组实现。跨维度导航和乘客迁移尚未接入；拆解、车站组装和车站时刻表交接不作为前提。

## 通过下界传送门

默认启用服务端配置 `netherPortalTransfers`。在主世界或下界建造并点亮原版黑曜石门框；门洞需要容纳整节车体及其下部转向架，入口处也要正确对齐。

无人、未连挂的单节车体接触门洞后自动尝试穿越，允许不超过 16 格/秒的低速行进及缓慢转动。按原版坐标比例寻找出口，找不到时调用原版逻辑尝试建门。原版新建门只有常规大小，较大的车体需要玩家事先扩大对端门洞；出口过小会拒绝搬移，原版新建门可能已保留在目标维度。没有额外扩建车体落区或清除沿途建筑。

两门朝向不同会把整组位置和姿态一同旋转 90 度，内部坐标与安装间距保持。整节放在出口外侧，不留下车尾穿在门中的状态。出口必须有完整净空，且每副转向架下方一格内需有支撑平台或铁路。到达后速度归零、驾驶台暂停并施加紧急制动；重新上轨并解除紧急制动后再驾驶。

成功后有 100 tick 冷却，随车体保存并使用主世界统一游戏时间；过期或明显时钟回退后不维持旧锁。失败时停止入口处车体、提示附近玩家，并等待 100 tick 再尝试。乘客、其他实体、连挂编组、未适配设备及运行中的子运动结构仍按基础迁移限制拒绝。

当前为整车瞬时穿门，不是半车跨维度物理或无缝门户渲染。原生轨道图的跨维度导航边仍未接入，时刻表不能因此自动选取另一维度的站点。手动命令保留供调试，不再是触发迁移的唯一入口。

## 命令与试用流程

需要权限等级 2。在单独的测试存档先准备目标维度的空地或支撑平台，停稳车体、暂停时刻表、退出驾驶、施加制动，并移走乘客和其他实体。

    /physicalrailways transfer list
    /physicalrailways transfer <物理体UUID> <目标维度> <x> <y> <z>

例如在主世界执行：

    /physicalrailways transfer <UUID> minecraft:the_nether 100 140 100

`list` 列出当前命令执行维度已加载的物理体 UUID、名称和位置，使用的是物理体 UUID，不是 `trains` 命令的逻辑列车 UUID。选中下部转向架时自动定位其安装座所属车体，再一起收集其所有下部转向架。普通无转向架结构也可以作为根物理体。

目标坐标是根物理体姿态的参考位置，保留其当前朝向；不会应用下界 1:8 比例，也不自动寻找轨道或修正落点。坐标含 `~` 时相对于命令来源解释。选取高处空地后结构仍受目标维度的重力影响，应准备适当支撑；本命令不提供悬停或安全着陆控制。到达后的转向架标记为脱轨，需要用已有操作重新上轨才能驾驶。

返回时在目标维度执行同样命令，或由管理员使用 `execute in <当前维度> run physicalrailways transfer ...`。UUID 保留；原维度的内部存储位置若已被其他物理体占用，返回也会拒绝。

## 首版支持边界

- 单节车体与其全部独立转向架，最多 16 个物理体、32768 个非空气方块、256 个粘合实体。
- 每个物理体包围盒体积最多 65536 格，整组目的区域最多加载 16 个世界区块。
- 车体内部粘合关系、普通无方块实体方块、物理转向架及款式、安装座、驾驶台及其物品、未连挂车钩、原版基础容器。
- 当前明确接受的 Create 方块实体类型为 kinetic、creative_motor 和 gearbox。清除它们及安装座的旧动力网络与动力来源引用，由目标世界重建。
- 保留刚体 UUID、名称、方块实体数据及完整匹配的逻辑列车身份；更新转向架所有权中的维度和修订号。
- 手动命令要求线速度不超过 0.05 格/秒、角速度不超过 0.01 弧度/秒，驾驶台必须暂停、退出接管并施加制动。门户入口允许不超过 16 格/秒及 0.5 弧度/秒，目标速度归零并自动停车。

以下情况拒绝操作：连挂中或待恢复的车钩、缺失转向架、未完成安装座交接、外部 actor 依赖、运行中的子运动结构、乘客和其他普通实体、未适配的方块实体、目标障碍物、超出高度或世界边界、内部存储位置冲突。

实体识别和碰撞检查采取保守范围，靠近车体的旁观者也可能使传送被拒绝。容器支持不等于任意第三方机器或可移式接口已兼容；同样不能将此版本当作多车厢或任意外部关节传送。

## 迁移流程与数据保护

`PhysicalTransfer.transfer` 仅允许同一服务端主线程调用，物理步执行中拒绝操作。完整预检后，先写压缩 NBT 备份并强制写入文件，再原子重命名；备份失败则不移除任何源成员。共享目标存储槽位不做全局规则修改，首版只在原有内部 X/Z 坐标空闲时加载，因此不批量改写其他模组的坐标数据。

维度最低高度不同的情况下，`TransferSections` 重新编号内部区块的 section，保持绝对内部 Y 坐标与容器 NBT；超出目标高度的实体方块不允许被静默截断。旧高度和光照有效性缓存失效。所有目标数据在私有副本上修改。

写好备份后，断开本节转向架运行约束，移除源粘合实体及源刚体，再在目标世界加载全部成员和粘合关系，并重新建立安装座到下部刚体的约束。运行期身份删除观察器只在本次同步操作期间保留成员身份；成功后将完整身份记录移到目标维度、注销源原生查询代理，并刷新源信号占用。门户到达后保留时刻表物品、项目进度及标题，清除旧车站和条件等待，不沿用旧轨道导向。

常规异常触发回滚，尝试删除目标副本、恢复缺失源成员及粘合关系、恢复身份记录。生产代码使用 `TransferRollback`：如果目标删除失败且副本还在，就不能恢复另一份源库存；其他成员仍继续恢复。回滚不完整时报告恢复未完成，保留备份和完整错误日志，不把部分恢复说成成功。

## 备份及当前恢复边界

备份目录为当前服务端存档根目录的 `guidedrailways-transfer-backups`。手动命令保留 `<操作UUID>.nbt`；自动门户按 `<根物理体UUID>.nbt` 保留最近一次备份，避免同一车体往返耗尽数量额度。内容包含操作编号、源/目标维度、源快照、目标快照及粘合实体。

只有旧状态为 Transferred 或 RolledBack 时，门户才能原子替换其上一份备份。新备份准备过程中先标记 Prepared，完成或回滚后更新状态；Prepared、RecoveryRequired、缺少状态及其他不完整状态都不能被后续门户操作覆盖。`.status` 文件不是世界提交凭据，也不触发自动恢复。

最多保留 32 个 NBT 备份，单份内存大小估计上限 16 MiB。满额后拒绝新的传送，不自动删除恢复资料。确认世界正常保存并不再需要恢复资料后，可由管理员归档这些文件。备份和状态文件不进入模组发行包或 Git。

目前没有自动重启恢复或恢复命令。NBT 备份也不是整个存档的一致性备份：世界区块、Sable 数据及身份 SavedData 不是跨文件原子提交。中途崩溃或断电后不能自动承诺无丢失、无重复，应保留整个存档与日志，核查两维度成员后再恢复；不要直接把旧库存快照覆盖到继续使用过的车体上。

目标区块同步加载以进行真实方块碰撞检查，原版寻门或建门也可能加载区块，冷区块生成可能造成一次性停顿。目标已加载物理体会检查碰撞；尚未加载的其他物理体是否随后进入该区域，仍需完整到达区块及存储索引预检。连续自动跨维度行驶接入前需要补充预加载、出口预约及恢复协议。

检测使用原版门户 POI 索引，每世界每 tick 至多检查 8 个物理体、执行一次寻门及迁移尝试；查询范围最多 64 格、最多读取 1024 个门户候选。短期观察最多保存 256 个 UUID，600 tick 未观察或时钟回退后清理；世界卸载释放。使用相邻观察的合理移动扫掠范围降低漏检，异常位置跳变不作为穿门。预算限制下大规模车体及密集门户场景仍需实际性能验收；不承诺任意速度及数量均不漏检。运行计时包含在 TrainRuntime.afterTick 的性能统计中。

## 已执行与待验收

离线检查：真实 NBT section 转换、箱内物品和名称保持、主世界/下界高度布局往返及越界拒绝，共 85 项；生产回滚算法注入目标移除前后、源恢复前后及目标不可查询异常，核对库存不复制、健康成员继续恢复及无关库存不变，共 66 项。门户几何、四分之一旋转往返、两轴正反向出口净空、过小门洞拒绝、停车时刻表物品保留及冷却时钟回退共 186 项；另有中英文语言、缓存边界、运行协调顺序及完整构建。这些不是 Sable 实际穿门的实机证明。

本轮未启动客户端或服务端。用户要求启动后优先在独立测试存档验收：

1. 原版箱子结构双向传送，核对 UUID、方块方向、箱内物品数量和名称。
2. 单节两副转向架，带驾驶台及已暂停时刻表，双向传送、重新上轨和重新驾驶；核对款式、安装关系、逻辑身份及旧车站/信号释放。
3. 带粘合区域的结构，传送后检查粘合实体及编辑行为，不能遗留源粘合或复制连接。
4. 移动中、乘客未下车、未暂停、未制动、已连挂、未知机器和外部对接，应拒绝且源库存保持。
5. 目标方块/实体/车体占用、存储槽位冲突、不同高度维度，应保守拒绝且不覆盖已有数据。
6. 迁移后保存重进、往返多次、两名客户端分别观察两维度，检查 Sable 跟踪、驾驶台及身份同步。
7. 在专用故障注入环境验证 Sable 加载失败和回滚；单元级回滚检查不能替代此项。
8. 不使用命令，让无人单节接触原版下界门，测试既有出口、原版自动建门、源门/出口过小、90 度门户、正反向进入、出口平台及回程；正确拒绝过快、无支撑和出口被占。
9. 保持车体位于门户旁、立即倒车返回、保存重进及反复往返，检查冷却、失败提示频率及每车备份更新，不产生反复传送或库存复制。
