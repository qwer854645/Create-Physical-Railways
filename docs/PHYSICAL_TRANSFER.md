# 内置物理体跨维度传送

2026-11-02：内置原版下界/末地门户、完整连挂编组、乘客及恢复协议。独立编写，使用当前 Sable 2.0.6、Minecraft、NeoForge 和 Create API；没有 AeroPortals 适配类、依赖或安装包，没有复制第三方传送实现。离线检查已执行，游戏内迁移与中断恢复尚待验收。

## 原版门户

服务端配置 `netherPortalTransfers`、`endPortalTransfers` 默认开启。

下界门按原版坐标比例寻找出口，找不到时调用原版建门逻辑。发现首次接触有效门区后立即尝试一次，不增加玩家式充能等待。入口不要求整列包围盒完全处在门洞里，也不按门洞宽高拒绝较大的车体；按原版实体的相对位置思路夹取入口偏移，过宽时居中，过高时按底部对齐。两端轴向不同会将整个编组及世界坐标中的乘客旋转 90 度。整列放在出口平面之外，底部留 0.05 格防止边界浮点误差。目标的方块、实体、物理体、世界边界及每副转向架下方的支撑检查继续生效；出口没有整列所需空地时仍拒绝，不挖除建筑。

末地门支持主世界进入末地和末地返回主世界。检测水平末地门户，接触者是车厢或其转向架均可触发，不要求整列塞进 3×3 水平入口。进入末地时落在原版平台位置附近；返回时落在主世界共享出生点东侧附近。按整列占地铺设最多 2048 块的黑曜石平台；返回主世界时先取占地内最高阻挡高度，再将平台铺在其上方。不挖除地形或建筑，平台位置被方块、实体或已加载物理体占用时拒绝。普通失败会撤回本次放置的黑曜石；中断时可能保留未使用的平台。

两类门户成功后速度归零，驾驶台暂停时刻表并施加紧急制动，保留时刻表物品、当前项目和标题，清除旧车站/等待条件。到达后需要重新上轨、解除紧急制动再驾驶。失败只制动并提示一次；仍接触同一门区时不再次寻门、验证整组、尝试搬移或发送失败制动更新，整组离开后再进入才可重试。连挂关系改变会重新观察编组。成功冷却为 300 tick，随车保存并使用主世界时间；冷却结束时若已经停在门里，仍需离开门区，避免原地往返。

这是完整物理体的瞬时迁移。跨维度轨道导航边、时刻表跨维度自动寻站、半车跨维度物理和无缝门户渲染不在本次实现内；第三方模组门户尚未接入。拆解、车站组装和车站时刻表交接不作为前提。

## 完整编组和实体

按已保存的连挂关系收集车厢，并校验每副独立转向架的安装座归属，不依赖暂时未重建的运行时关节缓存。任一成员、对端、控制器或绑定不完整时整次拒绝，不拆开传送。保留车体 UUID、列车逻辑身份、连接器端点/配对 UUID、几何、物品、流体和粘合区域；在目标方块实体加载前安装连接器所有权，避免克隆保护误改端点编号。

目标内部 plot 被占用时，先为整组规划空闲位置，同步修改已知的绝对内部坐标：方块实体、方块/流体计划刻、安装座所有权、连接器对端、储物库/储罐控制器和 LastKnownPos、内部实体位置及 pose 旋转中心。chunk key 保持相对位置，section 按两维度最小高度转换，绝对内部 Y 保持。主世界、下界和末地的转向架中心 Y 均为 128；其他高度布局仍需单独适配和验收。

乘客通过 Sable 当前追踪/乘坐归属或实际内部存储区判定，不按距离把旁人带走。包含站立玩家、生物、Create 座椅及乘坐树、内部装饰实体；一般实体必须能由原版保存和跨维度接口处理。玩家保留原实例和物品栏。迁移前触发 NeoForge 跨维度许可检查，限制事件取消则拒绝。带拴绳、归属不明或不能跨维度的实体拒绝迁移。

先解除乘坐和旧追踪，将内部实体临时移到世界坐标，避免 Sable REMOVED 清理内部实体；目标车体重建后再迁移实体并恢复乘坐关系。普通故障先解除目标追踪，删除目标副本，再恢复缺失源成员、实体、安装关系和身份。目标副本仍存在时不能再生成一份源库存。

支持本模组安装座、转向架、驾驶台和连接器，已接入端点适配的铁路硬件连接器，原版基本容器，以及 Create 的基础动力方块、储物库和流体储罐。储物库/储罐要求控制器完整、位于同一物理体且不处于移动重组中。未知设备、外部依赖/对接、运行中的子运动结构等仍拒绝，不能把“完整编组”理解为任意模组设备均已适配。不会猜测并改写任意第三方 NBT。

## 备份、提交和恢复

存档根目录 `guidedrailways-transfer-backups` 保存 gzip NBT 快照，最多 32 份，单份估计 NBT 内存上限 16 MiB。手动传送按操作 UUID 保留；门户按根车厢 UUID 保留最近一次记录，只有旧记录已完成或已回滚时才允许替换。包含源/目标快照、连接器、列车身份、粘合实体、乘客/乘坐关系及旧持久化位置提示。

版本 3 日志用小型原子 `.status` 决定记录绑定快照的操作 UUID。先原子替换快照，再写 Prepared；旧操作的完成记录不能提交新快照。Committed 代表恢复时选择目标，Prepared/RollingBack/RecoveryRequired 选择源。完成目标区块、Sable 存储、实体和相关 SavedData/玩家保存后才记录 Transferred；回滚保存完成后记 RolledBack。

服务端启动时只尝试恢复未完成记录，先加载已知旧存储区和两端实体数据，再检查编号及槽位冲突；删除两端受影响车体后，重建一个确定侧的完整快照及连接关系。完成记录不回放。无法确认槽位归属或遇到其他冲突时保留记录、打印错误并锁住相关 UUID，避免再次迁移覆盖恢复资料。旧版本备份不自动转换或回放。

离线玩家的恢复位置单独保存，重连时按车体当前存储中心换算位置，尝试恢复原座椅，保留其正常玩家物品栏；车体找不到时回到所记录维度出生点。后续迁移会更新未登录玩家的维度/位置提示。待恢复玩家和运行时 UUID 锁均有 4096 项上限，UUID 锁随服务端停止释放，未完成日志在下次启动重建它们。

需要权限等级 2 的命令：

- `/physicalrailways transfer list`：列出当前维度已加载物理体。
- `/physicalrailways transfer <物理体UUID> <目标维度> <x y z>`：指定根 pose 位置传送；也可选择下部转向架，自动找到所属车厢及完整编组。必须停稳、暂停时刻表、退出驾驶并制动。
- `/physicalrailways transfer recover <操作UUID>`：修复外部阻碍后重试未完成操作，恢复方向由持久化决定记录选择；不允许把已完成旧库存快照覆盖回继续使用的列车。操作编号可在服务端日志和快照中查看。

恢复日志不等同于全存档跨文件原子事务。断电、文件损坏、外部模组回调和磁盘错误仍可能使自动恢复拒绝执行，应保留完整存档及日志。不要删除未完成记录来绕过 UUID 锁，也不要手动复制库存快照。

## 性能边界

每次最多 128 个物理体、32768 个非空气方块、单个包围盒体积 65536、256 个粘合实体和 128 个一般实体。目的区预加载覆盖占地及一圈区块，最多 64 个区块，并推进 Sable 待加载数据再检查已加载物理体碰撞；预加载后再次校验预留槽位。超长编组可能先触发区块或平台上限。尚未进入预加载范围的巨大休眠物理体仍需要进一步验收，不能声称全世界休眠结构都已排除碰撞。

门户观察每 tick 最多访问 8 个体、进行一次新接触编组检查或迁移，最多保存 256 个 UUID，600 tick 未观察或时钟回退清理，世界卸载释放。完整编组共用接触状态，转向架和多节车厢不各自发起迁移；不通过逐 tick 读取 plot 中心方块来辨认独立转向架。未接触时缓存无门户结果，静止通常每 20 tick、移动每 5 tick 发现查询；明显移动会提前查询，合理扫掠覆盖前一次发现位置。车厢自身中心与含下部转向架的传感包围盒分开记录，避免静止被误判为移动。已知接触只读缓存锚点和成员包围盒，不查询 POI、扫描地形或反复枚举安装座。下界 POI 与末地 section 扫描原有限额保留。活跃接触不因缓存满而被淘汰后重新尝试；新接触超出容量时保守等待。

寻门、建门、冷区块生成和成功迁移时的保存屏障可能带来一次性停顿。当前 Sable 只公开按世界保存已加载物理体的接口；保存屏障不在逐 tick 无门户路径执行。完整构建和缓存检查不代替实机性能验证。

## 验收

离线检查包含：section 转换/货物 85 项、注入故障的生产回滚算法 66 项、门户几何/方向/停车/冷却 226 项、接触锁存/整组共用/离开重置与扫描节奏 15 项、真实 NBT plot 重定位/控制器/物品流体保持 103 项、操作绑定和中断边界 35 项，以及中英文语言、缓存边界、协调顺序和完整构建。

尚未启动客户端或服务端，以下需在独立测试存档实机验收：

1. 原版大小和扩大后的下界门：宽/高车体、低于入口的转向架、门边偏移、双向、90 度转向、正反进入、多节编组；有净空和支撑时不再报门洞大小错误，检查完整 UUID、配对、安装关系和到达停车。
2. 原版箱子、储物库和储罐：不同物品/流体数量、命名及多方块主从；检查往返后未复制、丢失或误拆分。
3. 座椅玩家、站立玩家、生物及内部装饰随车；车旁玩家留在原维度。双客户端分别观察源/目标，检查第一帧位置、视角和重新乘坐。
4. 主世界进末地、末地返回：长编组平台尺寸、已有平台复用、返回出生点附近、目标实体/建筑占用、尺寸上限和失败撤回。
5. 目标内部原槽已被其他物理体占用时改用空槽，验证连接器/安装座/储物库/储罐引用，检查多次往返保存重进。
6. 缺失/未加载对端、半个多方块、拴绳、未知设备、外部连接、过快、无支撑及跨维度事件取消时，源状态完整且不生成副本。
7. 在专用故障注入环境分别于 Prepared、Committed、RollingBack 阶段终止，重启核对只有一组车体、连接、库存和实体；测试离线玩家重连及 recover 命令重试。
8. 长时间停在门内只有一次失败处理，整组退出重进才重试；到达冷却及期间倒车入门不会原地往返。检查旧车站/信号释放，以及密集门户/大量物理体/冷区块保存耗时；不能把单元检查当作这些场景已通过。
