# 原版列车碰撞适配实验

## 范围

只对真实 Rapier 接触增加反馈。不增加距离预判、额外制动、速度目标限制或停车状态，不创建假 Train、额外碰撞壳或物理车厢。物理列车一侧仍由 Sable 原有接触求解，本适配不叠加冲量或修改其姿态。

Sable 2.0.3 已把 Create 车厢上传为运动学碰撞结构，但 Create 列车速度不会自然接收物理反作用。本轮在 Rapier 清理并返回真实接触报告时读取同一数组，原数组继续交给 Sable，不截断其音效或接触处理。

## 接口与处理

每个游戏物理 tick 开始记录本模组转向架和上部车体的速度、质量，以及已上传的原版车厢编号。报告每条 15 个 double：两个编号、接触力大小、两个局部法线、两个局部接触点。按实际编号匹配双方，法线转换到世界坐标，不通过包围盒距离猜测碰撞。

相同物理体与车厢的报告只保留接触力最大的一条，因为底层为每个接触点重复报告整面的接触力。只对相互接近的真实接触反馈；分离不处理。使用无弹性法向接触模型计算反馈，原版车沿轨道方向接受投影，使用已加载车厢的 Sable 质量之和。块/秒与 Create 块/tick 按 20 换算。只更新实际速度，不修改目标速度或调用服务制动。

源接口核对：[Sable 原生接触报告](https://github.com/ryanhcode/sable/blob/main/sable_rapier/src/main/rust/rapier/src/lib.rs)、[接触事件](https://github.com/ryanhcode/sable/blob/main/sable_rapier/src/main/rust/rapier/src/event_handler.rs)，并对本地 2.0.3 发布 jar 核对方法签名。

## 实验边界

这不是把原版列车变为完整动态刚体，也不是完全双向耦合的统一求解器。反馈在当前物理 tick 结束后进入 Create 的下一次运动，不能撤回本 tick 已发生的物理冲击；物理车侧仍有运动学物体接触的单向求解特征。高速撞击、复杂接触、多维度长列车的未加载车厢质量，以及同时有多个不同法线的接触需要实际验证。不能在测试之前宣称已彻底解决顶飞。

当前接入固定 Rapier 实现的接触数组和私有编号，升级 Sable 必须重新核验。其他物理后端不会加载这两个 @Pseudo 适配。544 项数值检查和完整离线构建通过，不代替游戏内碰撞验收。

## 待测

1. 原版车撞静止物理车，以及物理车撞静止原版车，分别低速正面和追尾
2. 两车反向运动后相撞，确认双方都有响应，且没有持续单方面推进
3. 斜向、弯轨接触，观察是否仍抬轮或顶飞
4. 接触后倒车分离，脱离后正常驾驶，不产生额外停车状态
5. 原版车撞原版车、物理车撞物理车，以及近距离平行错车的原有行为
