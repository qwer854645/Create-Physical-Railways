# 0.2.0 清理与回归说明

## 改动边界

本次统一内部实现，不调整驾驶手感参数。历史物品、碰撞布局、平台高度及车钩机构迁移代码已移除；旧版已放置车辆不保证可用，请在新测试存档验收。当前版本新建车辆的保存、恢复和可选模组适配继续保留。

## 已处理事项

- `TrainConsists` 统一每个世界的编组快照，控制台选举、自动驾驶、信号、到站、货运和动力分配共用成员关系。方向传播和轨道路线遍历仍各自负责方向与路线，不能用无向成员集合替代。
- 人工及轨旁连挂、解挂统一通知；主动改变编组时延后到主 tick 更新控制状态，避免重入。存档恢复和短暂卸载只使缓存失效，不主动清空保存的时刻表等待进度。
- 车站判断只读取当前编组的车钩，避免其他列车干扰本列车的方向判断。货运不再维护另一份成员关系缓存。
- `TrainCommand` 明确手动、时刻表和保持三种模式，`VehicleTraction` 负责动力分配及纵向力计算；删除重复的手动后备控制路径。
- `VehiclePlacement` 负责放置与整节上轨，`VehiclePhysics` 保留物理运行。跨世界遗留的待上轨选择会清除。
- `CollisionAssembler` 与 `BlockAssembly` 先检查全部目标再写入，质量刷新失败时恢复方块及运动状态，成功后才标记布局完成。没有改变的目标同样参与提交前校验。
- 碰撞部件从 style × gauge × part 的 20,480 种状态改为 1,220 个实际 shape ID，中心转向架只保留 40 种款式状态。动态形状按需缓存，最后统一优化布尔并集。同步重建质量选择器及覆盖所有状态的模型声明。
- 删除 narrow_bogie、wide_bogie、monorail_bogie 注册、模型、转换配方、翻译，删除未使用的五款几何目录及生成脚本、只写不读字段和历史高度/插座转换。保留无 Railway 环境必需的独立默认车型。
- Java 源码统一排版；单独提交，排除注释和 import 后的可执行 token 不变。

## 已完成的自动验证

- 完整离线构建及全部 check 任务通过，包含语言、驾驶、制动、岔路、信号、上轨、时刻表恢复、货运及车钩检查
- 编组图使用 250 个固定种子的随机案例，与独立可达性计算对照，覆盖孤立车体、无转向架的中间车体、自连接与重复边
- 碰撞目录检查所有 shape ID、单元对应关系和质量选择器；普通车型总质量仍为 80，只有中心单元的隐形车型为 48
- Minecraft 实际 VoxelShape 的 16 个代表性单元与原布尔并集结果一致，缓存对象可复用，不创建服务器或世界
- 回滚检查覆盖目标占用、规划后变化、部分写入失败、质量刷新失败及回滚自身失败
- 实际 Minecraft NBT 检查车钩身份、对端、插座、固定长度和未完成动画时间线的磁盘往返，并拒绝历史几何版本
- 与清理前提交 5f93c73 对照：39 个 Railway 车型的全部当前几何与挂载数据一致，仅删除历史高度元数据；DriveModel、DriverModel、TractionBudget、DerailmentModel、TrainConfig、CouplerGeometry、CouplerMechanism、NativeContactModel 的可执行 token 一致
- Railway 固定 Beta 版契约检查通过；39 个车型的 241,980 个动画表面采样被碰撞覆盖

自动检查不能代替游戏内验收，下面场景仍需玩家观察。

## 客户端回归场景

1. 新存档分别放置标准、窄轨、宽轨、单轨及长轴车型；检查贴图、平台标高、玩家碰撞和车轮碰撞
2. 放置在直轨、弯轨及物理体底部；多转向架整节重新上轨，确认空间不足时不发生部分移动
3. 单车、载重车、多车连挂，分别测试应力驱动、手动档位、正反向、滑行和制动，与原有速度和加速表现对照
4. 链接工具与轨旁车钩均测试连挂/解挂；同一世界运行两列独立列车，检查控制台、到站、信号和分支选择互不干扰
5. 时刻表行驶及到站等待期间退出重进，检查车钩实体关节恢复、时刻表继续运行和等待进度
6. 自动到站后的物品、流体、包裹地址过滤和对接解除；观察连挂/解挂后货运成员是否即时刷新
7. 直轨正面及追尾碰撞、用手杖接触后倒车脱开，确认轮组不会互锁或弹飞；测试行驶中的外观与视野边缘渲染
