## BnB 转向架

统一物理转向架物品保持不变。主手持物品，潜行右击打开 BnB 原生款式菜单，选定类型、轮轴数量、尺寸和长短后确认，再右击铁路或物理体底部放置。安装 Railway 时原有选择菜单继续可用，BnB 自带的菜单切换按钮也继续保留

物理转向架用独立的服务端款式／尺寸记录，避免两个模组的菜单数据包覆盖彼此的尺寸选择。仅接受主手持物理转向架时提交的、已注册且具有本项目几何目录的组合，不能用客户端数据指定任意碰撞或尺寸。该记录随玩家保存，模型用安装的 BnB 原生动画及纹理

采集涵盖 96 组 BnB 款式／尺寸，与原有 39 组共计 135 组原生几何。原有款式索引和碰撞 shape ID 保持原顺序，新款追加到目录末尾。根据 12 个转动相位生成 1/16 格碰撞包络，每个转向架仍是一个下部刚体，安装座使用原有车体刚体，不为轮子新增物理体

极长六轴款可以超过历史的 127 个碰撞单元限制；现在碰撞单元用独立整数 shape ID，已移除不再适用的旧限制。模型较长会增加该刚体的复合碰撞复杂度；静态扫掠包络仍有近似，不能把表面覆盖检查当成行驶验收

0.2.10 的新放置使用紧凑平台：39 组款式可降低一格，平台下表面按原生动画完整转向包络避让，中央轴座与整数格顶面保持一致。平台形状按款式缓存，最多 19 个合并片段，不新增刚体；模型 UV 连续映射，模型与实际形状使用同一组坐标

旧平台的 `compact=false` 状态保留原模型和轴座高度，保存重载、粘合移动及重新上轨继续沿用该高度；不会下移已有车体。新放置的 `compact=true` 状态独立保存。需要降低旧平台时先拆除再放置，不自动移动整车

平台使用动态形状，并分别提供完整的顶部支撑面与顶部交互面。离线检查覆盖所有 136 组款式的两种状态：顶面完整、上方第一格不被平台形状占用、中央／边角射线命中朝上表面，以及平台下表面对原生动画的转向避让。若游戏中仍无法放置，服务端会输出 `[MountPlacement]`，记录目标是否可替换、方块是否能存活及是否被实体遮挡；不会绕过玩家或其他实体的正常放置限制

0.2.11 的日志确认，平台上方的方块位置可替换、能存活且未被实体遮挡，但 Sable 的 `BlockPlaceContext.canPlace` 仍返回 false。其跨物理体建造检查把对方每个不可替换方块当作完整一格，隐藏碰撞格内的空白也因此阻挡建造；0.2.10 的支撑面修正没有触及这一层

当前在 Sable 合并到 BlockPlaceContext 的 `sable$intersectBlocks` 中，只对“向平台正上方放置，阻挡体为该平台绑定的转向架，阻挡方块为本模组构架／隐藏碰撞格”的情况，改用实际 VoxelShape 分解后的有向包围盒 SAT 复核。只有实际形状不相交时才清除此格的误判，其他物理体、世界方块及原版实体／权限／方块存活检查保持原流程。旧平台和紧凑平台均可使用，不要求重新放置

离线检查用实际 Sable SAT 复现了 753 处整格误重叠，48,538 项几何和注入契约检查通过。另核对 Sable 2.0.0～2.0.6 的上述放置 Mixin 字节码完全相同，检查了注入优先级、唯一调用点和局部变量结构。完整构建及现有 38 个支持发布版的静态检查通过；运行时注入与游戏内放置效果仍待玩家验收，不自动启动客户端

## CEE 接触网牵引

在包含物理转向架与驾驶台的车体上放置 CEE 原生受电弓，并按 CEE 的方式修建、供电和升起受电弓。不需要给安装座接机械应力；驾驶台牵引档和时刻表沿用现有操作。受电弓接触检测、升降动画和世界接触网电路均由 CEE 负责

手动驾驶步骤：

1. 把转向架、车体、驾驶台和 CEE 受电弓装在同一辆物理车上；受电弓应安装在车顶，不能只放在旁边的地面上
2. 使用 CEE 的电源和接触网，让受电弓接触处真正带电。当前默认最低列车电压为 1900 V，可先用 3000 V 测试，再按需求调整电源容量
3. 检查受电弓已升起并接触线路。空手右击受电弓会切换升降，已经升起时不必再点；只有线在附近、没有实际接触，不会供电
4. 空手右击本模组驾驶台进入接管状态，再对准驾驶台长按右键，上下移动鼠标或使用滚轮调节操纵杆。新驾驶台初始在制动档，需要越过滑行位置，进入正牵引档才能开车
5. 蹲下右击驾驶台打开 GUI，可在停车时选择方向；若时刻表正在自动运行，需要在 GUI 使用接管按钮切换为手动驾驶
6. 左键紧急制动，Esc 退出接管。退出接管保留原驾驶设置，并不等于停车

受电弓通过本适配直接为整列物理转向架提供电驱预算，不要求另外安装电机、蓄电池或给应力输入接轴。同一副转向架若仍有机械应力输入，机械动力优先；初次测试可断开应力输入，单独确认接触网牵引

本模组通过公开的 `AddToElectricGraphEvent` / `FinishElectricSimulationEvent` 接入电路，一串连挂车厢共用一个牵引负载。受电弓仍通过原生设备接入实际接触网；不是读取“附近有电线”就直接提供动力

- 正牵引档根据加速／巡航状态，按需使用 CEE 原生列车的每副转向架功耗配置，停放时只保留小待机负载
- 返回路径沿用 CEE 原生列车对地回路的处理，不要求额外给车体铺设回流电缆
- 读取实际端电压与电流；低于 CEE 列车最低电压时电驱输出为零，实际可用机械功率取电功率的 85%
- 电驱等效输入为 256 RPM，目标上限仍由本模组 `maxTargetSpeedAt256` 决定；它是驾驶速度上限，不把等效 RPM 写进机械应力网络
- 牵引力受现有加速度／转速力限和实际电功率共同限制；启动处使用有限速度下限，避免除零或无限启动牵引力
- 服务制动与紧急制动独立于接触网；降弓、无电区、断电与结果过期时不继续提供电驱牵引，不实现回馈制动
- 机械应力输入保留优先权；同一副转向架有有效机械输入时沿用原动力预算，不额外叠加免费电驱力

该适配连接的是受电弓电力和物理列车动力。CEE 原版 Train 专属声音、随车仪表数据包、原版列车蓄电池行为不在本次实现范围；普通电机驱动应力仍走现有机械传动

成员关系和供电结果按实际编组绑定，世界退出时清理缓存；受电弓列表只扫描已加载物理体区块，每秒刷新，不强制加载其他区块。电路构建和结果事件在 CEE 主线程阶段执行，后台求解阶段不读取或修改车辆

## 检查与验收

离线检查：`gradlew.bat build --offline`、`python verification/check_all_bogeys.py --capture build/bogey-capture.json`。电驱模型检查功率上限、低电压、反向和断电制动；发布包电路检查用实际 CEE 电路节点、负载与结果 API，不创建服务器或世界

已完成四种主菜单加载组合：同时安装、均不安装、仅安装 BnB、仅安装 CEE（这些组合均保留 Railway）。无 Railway 的 BnB 组合在加载期间退出，未完成验收。用户已要求停止自动启动；后续仅做离线构建和日志检查，只有用户明确要求时才启动客户端


玩家回归场景：

1. BnB 小型、大型、超大型与长轴款：选择、预览、直轨／弯轨放置、平台接合、玩家及车体碰撞
2. BnB 菜单与 Railway 菜单来回切换，检查选定尺寸不会被另一套数据包覆盖；重进后再放置
3. 受电弓升起与降下、带电与无电接触网；驾驶台正反向牵引、滑行、服务制动与紧急制动
4. 多受电弓、多转向架、带载、连挂与解挂；不同列车不得共享供电节点，解挂后的无弓车厢不能继续凭旧供电结果驱动
5. 带时刻表的自动运行、到站等待、断电后重新供电，以及保存退出重进

主菜单启动和离线检查不证明上述游戏内效果已经通过
