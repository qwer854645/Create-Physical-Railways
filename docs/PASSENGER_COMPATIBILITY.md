# 玩家乘客条件兼容

版本：0.1.45 · Create 6.0.10-280 · Sable 2.0.3

## 实现范围

支持原版时刻表的 `PlayerPassengerCondition`，读取原版 `getTarget()` 和 `canOvershoot()`，分别比较人数相等或大于等于。等待步骤仍按同组顺序完成、不同组任一完成的规则执行。

`TrainPassengers` 从本维度在线玩家的实际坐骑读取 Create `SeatEntity`，根据座椅锚点所在 Sable 车体归属汇总。车钩编组沿用 `CargoStorage.consist` 的连接关系，包括无转向架的车厢；不遍历世界所有实体、不按玩家与车体的距离猜测、不加载新区块。每个活跃乘客条件的开销约为编组遍历加本维度在线玩家数，未扫描整车方块或库存。

只计存活、非旁观模式且实际坐在 Create 座椅中的玩家。站在车体、驾驶台接管、动物、其他模组座椅及原版矿车不计入人数。多人同车、一个车体多副转向架不会重复统计。车体中的座椅由原版 Create 和 Sable 管理，本模组不创建替代乘坐实体。

编组不完整或相关座椅区块未加载时不完成条件，特别是不能用缺失信息满足“恰好零人”。运行中编组变化沿用现有暂停保护；重新继续后接受当前编组。保存已完成的分支步骤，未完成的人数条件每次重新检查实际玩家，不用 `PrevPlayerCount` 决定是否满足条件。人数变化记录 `[PassengerWait]`，步骤完成记录 `[ScheduleCondition]`。

本次核对了锁定版本 Create 座椅实体的方块位置验证、乘客条件接口，以及 Sable 对车体内乘坐实体的坐标处理。未改动第三方模组，也没有伪造 Create Train。多人断线重连、实际座椅与物理车体的联动仍需要客户端验证。

## 客户端测试场景

1. 单车在 A 站等待至少一名玩家，空车不发车；玩家坐上车载 Create 座椅后前往 B 站
2. 使用“恰好零人”，坐着时保持等待，下车后发车；站在车上和接管驾驶台不能被计为坐席乘客
3. 两名玩家分坐头车与后车，设置“恰好两人”；先一人时等待，两人齐全后发车。再用“至少一人”验证超额人数也能完成
4. 同一车体装多副转向架，仅一名乘客时“恰好一人”应成立；无转向架但由车钩连挂的车厢中乘客应被计入
5. 同站其他列车、站台座椅和动物乘客不能满足本车条件。旁观模式不计数
6. 同组使用延时再人数条件、另一组使用红石条件，检查顺序和任选分支；已完成条件无需在之后持续成立，这沿用原版等待步骤语义
7. 等待人数时退出重进，确认时刻表保留且按重新登录、实际坐下的人数判断；已完成步骤保持。人数日志不应每刻刷屏
8. 等待中连挂或解挂，应暂停并提示编组变化；确认继续后按新编组人数运行。车厢未加载完整时不得误认为空车

自动检查：`checkPassengerManifest` 覆盖编组归属、去重、相等/至少比较、零目标、解挂、缺失加载和重载后不沿用旧人数。检查不启动 Minecraft，不能替代上述实际乘坐流程验收。
