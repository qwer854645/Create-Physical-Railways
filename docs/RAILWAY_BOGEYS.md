# Railway 转向架选择（0.1.60）

覆盖锁定的 Steam ’n’ Rails NeoForge `0.3.0-beta.2+neoforge-mc1.21.1` 与 Create 标准款的全部 **39 种款式／尺寸组合**。这是注册目录覆盖范围，不代表每种组合都已完成游戏内驾驶验收，也不包含额外的倒挂安装模式

## 选择与放置

所有转向架统一使用一个物理转向架物品。主手持物品，按 Railway 的转向架菜单绑定键打开原生界面，选择款式；尺寸按钮切换该款支持的小型／大型尺寸，只有一个尺寸时不可切换。预览固定显示将要放置的款式与尺寸，不再轮播其他组合。确认后右击铁路放置，或右击物理车体底部安装

标准小型款按目标铁路自动选择普通、宽轨、窄轨或单轨基础款；其他选择保留自己的轨距，不匹配时拒绝放置。安装在物理车体底部时没有目标铁路，自动标准款按普通轨距安装。大型、多轴蒸汽机轮组需要更长的连续轨道和更大的安装空间

创造栏只显示统一物品，拆除任何轨距均返还此物品。不再注册 narrow_bogie、wide_bogie、monorail_bogie 或提供历史物品转换。已放置转向架不会随菜单改选而改变，换款需拆下重新放置。菜单记录本身的跨会话保留沿用 Railway 行为

## 原生外观与动画

直接调用安装模组的 `BogeyStyle.render`，引用原模型、纹理和动画，不复制材质。原生入口内部有 −1.5078125 格的 Y 平移，本版补偿该平移，修复旧适配中模型整体过低、陷入轨道的问题

菜单图标先使用原生资源；锁定 Beta 中缺少的单轨、手摇车图标使用其已有通用图标回退，资源包提供图标时仍使用原图。隐形款本来就不显示模型，不属于缺图

轮转角由实际行驶距离和踏面半径计算。手摇车原生动画将输入角度放大两倍，本版在输入端补偿，使其显示轮速与位移一致。轮组不增加独立旋转刚体

## 碰撞、安装高度与保存

通过实际原生渲染器采集 12 个轮转相位（每 30° 一次）的变换后顶点，测量轴位、轮径及整副外形。轨道导向前后采样间距、踏面高度、安装座高度按所选款式计算，安装座顶面对齐整数格。0.1.60 按一格方形平台绕中心转动的扫掠范围（半径 √0.5 格）检查上方空间，保留至少 1/8 格间隙；不再被远离平台的轮缘、连杆最高点无谓抬高。0-4-0、0-8-0、0-12-0、宽轨大型标准款降低一格，宽轨超大型从四格降到三格。其他款式仍需避让回转范围内的高轮或机构。支座下沿按 12 个动画相位中保持不动的中央构架表面计算，避免把手摇车运动摇杆当成承载面；支座模型和碰撞共用同一个下沿数据。同车体混装大小轮组重新上轨时，逐副计算自己的几何尺寸

碰撞以 1/16 格精度对采集的表面及动画包络体素化，在每个碰撞方块内合并包围盒。它仍是静态扫掠包络近似，不是逐帧变化的三角面碰撞；狭长蒸汽机刚性轮架在急弯可能出现切弯外观，需要游戏内验收。防互卡的转向架间接触范围也随模型长度更新

各款碰撞分布在原有下部物理体内，不为每个轮子增加物理体。每款占用少于 127 个碰撞单元。普通可见款总质量保持 80，隐形款保留质量 48 的中心承载块。质量按实际碰撞分布分配，避免旧款角落配重误套到新款

款式以当前目录索引保存，每个实体保存原生 BogeyData。碰撞部件使用扁平 shape ID，总计 1,220 种实际形状，按需构建 VoxelShape；安装座和转向架各 40 种款式状态。平台按当前款式直接计算高度，不再读取历史高度版本或转换旧碰撞布局。0.2.0 不保证旧版已放置车辆兼容，建议使用新测试存档。

## 可复现检查

依赖包 SHA-256：`64b74ddad661deae1cfe7e8334cfa3d39bb8ef7b761f83595ba0476c4a9bb1d5`

开发者执行 `gradlew.bat runClient --offline -PcaptureBogeys`。采集器只在主菜单且资源加载完成后运行，不创建世界或服务器；输出 `build/bogey-capture.json`，完成后关闭客户端

随后执行：

```text
python verification/generate_all_bogeys.py
python verification/check_all_bogeys.py --capture build/bogey-capture.json
gradlew.bat build --offline
```

生成脚本更新款式几何目录和质量数据；检查脚本验证目录、依赖哈希、稳定索引、碰撞容量，以及 12 个相位的采样表面覆盖。自动检查不证明实际转弯、接触手感或 UI 布局正确

## 客户端验收

1. 手持统一物品打开菜单，检查单轨、手摇车图标，以及尺寸按钮、预览和最终放置款式是否一致
2. 放置普通双轴、三轴、大型蒸汽机多轴款，观察贴轨、安装座连接、正反向轮转和连杆动画
3. 分别放置宽轨、窄轨和单轨款，检查标准小型款自动选轨距；隐形款应可承载但不显示轮架
4. 直轨与较缓弯轨放置、车底安装、低速过弯；长轮架检查空间不足提示和急弯外观
5. 不同款式正面、追尾和斜向接触，倒车及物理手杖应能分离，检查明显穿模和轮组互卡
6. 同车体混装大小款，重新上轨、保存重进、卸载恢复后，检查款式、平台高度、碰撞和动画
7. 用当前版本创建车辆，退出重进，回归驾驶台、应力输入、车钩和时刻表恢复

0.1.60 验收补充：新放置及重新上轨后，在水平轨道上用整方块垫至平台高度，平台顶面应与整格层面齐平；分别检查小型款、上述五种降低款、仍保留较高平台的蒸汽机及手摇车款。斜坡以轨道局部方向放置，不承诺世界 Y 坐标始终为整数


## 0.2.3 渲染入口与性能回归

NeoForge 的 IBlockEntityRendererExtension 默认 getRenderBoundingBox 只返回方块自身的一格 AABB，不读取 Create CachedRenderBBBlockEntity 的模型包围盒。Sable 的 NeoForge 裁剪钩子直接读取渲染器入口并转换到世界坐标，因此仅覆盖方块实体的 createRenderBoundingBox、或仅开启 shouldRenderOffScreen，不能解决该路径的边缘消失。

转向架渲染器现在明确返回完整模型包围盒，并加入一 tick 线速度余量；包围盒覆盖全动画碰撞目录中的几何，按款式惰性缓存，避免每辆同款车重复遍历模型。距离判断改为到模型包围盒的距离，范围随客户端有效区块渲染距离设置，至少 64 格，不再使用固定 64 格的方块中心判断。仍保留视锥和距离裁剪，不无限渲染所有车辆。

离线验证使用 Minecraft 实际 Frustum：中心方块完全离开视锥而轮子仍伸入时，完整包围盒保持可见；覆盖全部 35,261 个车型几何盒，并检查超出 64 格、长模型前端、超出显示范围及 Sable plot 坐标下的距离判断。此检查不替代游戏内边缘和远距离观测。

同时移除两处规模放大开销：信号系统不再每 tick 重建整份 AutomaticNavigation，而是按轨道索引 generation 失效，并同步清理路线桥接缓存；导航构建按目标图取路径，避免扫描其他图。编组连接按成员分区一次分配，保留原连接顺序，随机图回归与旧筛选结果一致。行驶力、制动及轮轨约束参数未更改。

客户端回归：普通/长轴款在视野边缘及远处是否仍随车体可见；动态行驶时轮组边缘显示；信号、时刻表岔路、修改轨道后的缓存更新。完整离线构建、语言及 Railway 契约和动画覆盖检查通过，实机验收待用户反馈。


## 单轨接触适配（0.2.5）

锁定的 Railway Beta 对水平单轨提供整格宽、15/16 格高的实体碰撞盒。它包住了单轨转向架的侧轮和下部结构，与本模组的轨道导向约束同时作用时会产生穿透纠正和摩擦，直轨上也可能卡住或抖动

本模组通过 Sable 原生 `BlockWithSubLevelCollisionCallback` / `CollisionResult.removeCollision` 接口，在原生求解器处理接触时只排除以下一组：世界中的单轨轨道，与仍处于导向状态的单轨转向架中心块或碰撞部件。检查车体 UUID、款式轨距和导向状态；不额外施力，不改变驱动或制动参数

玩家、普通物理方块、车体上方结构、其他轨距转向架、脱轨后的单轨转向架，以及物理体上的轨道均保持原有碰撞。模型与碰撞几何目录不变，不修改 Railway 依赖包，也不需要重新生成旧车辆的碰撞布局

客户端回归：直轨新放置后静置、低速正反向、高速行驶；直轨进入弯道；原有单轨车辆重载存档；玩家站在轨道上；普通物理方块及另一副转向架与其碰撞。启动日志应出现 `[MonorailContact] selective guided-bogie callback registered`，它只确认接口挂接成功，不代表游戏内行驶已经验收
