# Railway 转向架选择（0.1.58）

手持本模组的物理转向架，按 Railway 的“转向架菜单”绑定键打开原生界面，选择款式并使用界面确认操作。右击铁路放置，或右击物理车体底部安装。按键支持重新绑定，物品悬停提示显示当前绑定；本次会话已确认的款式也显示在提示中。菜单的取消行为保持 Railway 原样。

所有转向架统一使用一个“物理转向架”物品。创造栏只显示此物品，拆除任何轨距均返还此物品。旧 narrow_bogie、wide_bogie、monorail_bogie 注册 ID 保留以读取旧存档，名称和外观与统一物品一致，放置同样读取当前菜单选择；旧配方改为单个旧物品无损换回统一物品，不再合成新的分轨距物品。

首批原生款式仍为 SMALL 尺寸的 FREIGHT、PASSENGER、MODERN、BLOMBERG、Y25，均为普通轨距。STANDARD/SMALL 会按目标铁路自动选用既有普通/宽/窄/单轨几何，通用轨道选择普通轨距。MONOBOGEY/SMALL 指定单轨，WIDE_DEFAULT/SMALL 和 NARROW_DEFAULT/SMALL 分别指定既有宽/窄轨基础几何；这些基础几何沿用本模组原来的渲染，不宣称已校准对应全部原生型号。专用款式与目标轨距不符时提示原因。

菜单保留 Railway 的完整目录，但未校准款式/尺寸在服务端放置前拒绝，不消耗物品、不创建物理体。暂不支持已放置转向架直接换款，拆下后重新选择并放置。右击物理体底部安装时没有目标铁路，自动标准款按普通轨距安装；显式轨距款式保留其轨距。

服务端读取 Railway 自己的玩家选择记录，客户端不能通过显示状态直接指定服务端碰撞。款式用稳定的方块状态索引保存；原生默认 BogeyData 随转向架 BlockEntity 存储和同步，额外记录 NativeBogeyStyle 以便诊断。每个实体独立持有渲染数据。旧存档缺少 style 属性时为 DEFAULT=0。已经放置的款式不随其他玩家或自己的菜单改选而变化。原生菜单记录本身的跨会话保留行为不在本模组修改范围内。

使用原生 BogeyStyle.render 引用安装模组的模型、纹理和动画，不复制渲染资产。五款原生渲染器均采用前后 Z=±1 格、轴心 Y=0.75 格的小轮布局，与现有导向和平台高度匹配。轮转角来自实际行驶距离除以踏面半径，不按牵引目标空转。

各款固定构架碰撞由原 OBJ 每个对象的顶点包围盒测量，轮组使用踏面/轮缘/轴的静态扫掠包络；仍是部件包围盒近似，不是逐三角面碰撞。测量数据含原 OBJ SHA-256，可运行 `verification/generate_bogey_profiles.py --check` 对安装 Beta 复核。物理形状按款式分区到已有转向架物理体的碰撞方块中，不增加每轮刚体。渲染范围和原有防轮组互卡的转向架间接触包络均按所选款式更新。原有 DEFAULT 四轨距碰撞保持。

## 客户端验收

1. 主手持普通物理转向架，打开菜单、选择并确认 Y25，然后放置；依次回归其他四款。默认铁路机壳仍能正常打开 Railway 菜单
2. 重新绑定菜单键，检查物品提示和打开操作；取消菜单后检查选择是否符合原生行为
3. 选择大型/多轴款，放置应提示未适配；普通双轴款对准宽/窄/单轨铁路应提示轨距不符，物品不消耗
4. 直轨/弯轨放置、物理车体底部安装、低速转弯，观察车轮贴轨和平台连接处
5. 两种不同已支持款式直轨正面/追尾及斜向接触，倒车和物理手杖应能分离，不重复出现轮组互卡
6. 保存重进、卸载恢复后，检查款式、碰撞、轮子动画和驾驶；一辆改选下一次放置款式，不应影响已放置车辆
7. 同一个物品选择 STANDARD/SMALL，分别对准普通/宽/窄/单轨铁路放置；拆除后应都返还统一物品，旧三类物品可单个合成转换；回归现有驾驶台、应力输入、车钩和时刻表

自动检查不能代替上述游戏内验收。大型轮组、多轴、倒挂等款式留待下一批单独校准。
