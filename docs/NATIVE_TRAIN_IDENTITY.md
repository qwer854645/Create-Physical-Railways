# 原生列车身份与车站关联

适用：0.2.24 · Create 6.0.10 · Minecraft 1.21.1 / NeoForge

## 已实现的范围

每个已加载、连挂恢复完整且包含有效主驾驶台的线性物理编组，在 Create.RAILWAYS.trains 中注册一个 PhysicalTrainProxy（Train 子类）。客户端在 CreateClient.RAILWAYS.trains 中保持同类代理。

- 有效主驾驶台由现有编组主控选举确定；不要求玩家正在接管，不要求通电，也不要求时刻表正在运行
- 整列只需一个驾驶台，无驾驶台的挂车连入后属于同一列车；拆掉最后一个驾驶台后撤销服务端与客户端活动注册
- 从未安装驾驶台的散装转向架不分配列车身份；已注册列车暂时移除驾驶台时可保留休眠身份，重新安装后恢复
- 稳定 UUID 独立于驾驶台，成员按转向架物理体 UUID 保存
- 连挂合并保留一个已有身份，另一身份退役；解挂后包含身份锚点的一组保留 UUID，其他组创建新 UUID
- 身份锚点被确认删除时，剩余成员接替锚点；卸载不等于删除
- 数据保存在当前维度的 guidedrailways_trains SavedData 中
- 已知成员尚未恢复、或保存的车钩尚未恢复时，暂不发布这一编组，避免错误拆成多列车
- 每个物理车体对应一个逻辑 Carriage，同体多转向架使用首尾转向架描述原生车厢，中间支承仍由物理系统处理
- 提供默认名称、UUID、车厢位置、维度、实际速度、轨道关联和保守长度估算
- 速度转换：物理后端格/秒除以 20，转换为 Create 的格/tick
- 五 tick 刷新服务端代理，十 tick 同步客户端；新建、移除和玩家登录额外同步
- 没有新增世界实体、物理体、碰撞箱或可见车厢

原生车厢间距与转向架间距是整数，本阶段做取整表达；列车长度按物理体世界包围盒和车体间隙保守估算。它们仅用于查询，不参与牵引、车钩或碰撞求解。

## 隔离边界

代理 earlyTick/tick 不执行原版运动、时刻表或信号更新；逻辑车厢不生成实体。原版拆车入口对代理返回不可拆。代理的 arriveAt/setCurrentStation/leaveStation 入口仍不执行原版副作用；实际关联仅由经过停稳验证的车站桥接更新。

三处定点 Mixin 只过滤 PhysicalTrainProxy，原版列车保持原路径：

1. 原版登录 AddTrainPacket：代理使用自定义快照，避免客户端被解码成普通 Train
2. RailwaySavedData.save：代理不保存为普通列车，避免重进后由 Create 生成重复车厢
3. Train.findCollidingTrain：避免代理触发第二套原版列车碰撞；原有 Sable 接触兼容保持不变

用户要求保留的单轨回调检查完全不变。

## 0.2.15 原生车站关联

沿用现有轨道方向、头部位置与停稳检测：距停靠点不超过 0.25 格、速度不超过 0.12 格/秒连续六 tick 后确认；已到站后允许小幅物理抖动，偏离超过 0.5 格或速度超过 0.2 格/秒即离站。高速经过、反方向车站、组装中的车站、脱轨和未完整恢复的编组不建立关联。停靠期间锁定到达时的物理轮轴参考，原地切换方向或驾驶员不应因“车头”改到另一端而错误离站。

关联通过 GlobalStation.reserveFor(proxy) 和代理 currentStation 建立，满足原生 GlobalStation.getPresentTrain()/getImminentTrain() 的双向验证。不会调用 Train.arriveAt()，避免提前推进原版时刻表或触发原版邮箱交换。其他原版列车或非本桥接持有的预约不会被覆盖；重叠车站和多个物理列车采用稳定的单站单车选择。

已删除 GuidedPhysicalPresent 客户端标记与 StationBlockMixin 比较器覆盖。旗帜、原生到站 UUID、列车名称展示及比较器改由 StationBlockEntity 原生 tick 驱动。原生车站计算机事件现在有条件沿此入口识别代理，但未做外部计算机模组的客户端验收，也不代表其全部列车 API 均已兼容。

离站、移动车体、拆除最后一个驾驶台、编组改变、车站删除、代理移除或世界卸载时解除旧关联。取消预约只作用于本代理，不清除其他列车预约。重新进入存档后根据实际位置重新确认，不保存一个可能失真的到站占用。

客户端快照携带车站 UUID，在客户端原生轨道图就绪后建立查询关联。现有身份查询命令增加“车站”字段，仅在 getCurrentStation 与 getPresentTrain 均匹配时显示站名。

物理列车的时刻表仍存放在驾驶台，原生车站的自动发放和取回时刻表入口对代理保持隔离，避免给空的原版运行器发放任务或取走错误物品。物理包裹取送接受本站为当前列车自身占用，其他列车占用时仍等待。

## 本阶段未迁移的功能

现有驾驶台、时刻表执行器、停稳检测、导航、信号占用和物理碰撞仍由原系统负责；停稳结果现在驱动真实原生车站关联。0.2.16 增加 Navigation 与 ScheduleRuntime 的查询投影，不执行原生导航或时刻表。代理仍不提供原生货物和旅客视图或完整列车编辑功能。0.2.18 由驾驶台管理并保存列车名称，原版列车编辑界面不是写入来源；0.2.19 增加基于驾驶台放置记录的所有者查询。

环形或分支车钩网络、没有转向架的独立中间车体暂不发布代理。多副转向架不会因此新增原版车厢实体。跨维度行驶不在本阶段范围。

## 0.2.16 导航与行程查询

主驾驶台是唯一状态来源。NativeTrainJourney 每五 tick 读取现有 ScheduleController 的结果，随身份快照每十 tick 向客户端同步；不会再次运行寻路、发出牵引或制动指令。未改变现有车速、信号、车钩和站名匹配规则。

- 原生 Navigation.destination、distanceToDestination、distanceStartedAt、destinationBehindTrain 对应已确认路线的目标站、剩余格数、起始路程与相对代理车头的方向。只对路线、铁路图、编组和头部引用仍有效的计划发布；反向不直接使用驾驶台方向冒充代理车头方向
- 快照保存尚未经过的完整有向轨段；原生 currentPath 只映射未来分叉选择，使用现有 TrackNode 对象。客户端节点或车站未同步完成时不发布部分路线，后续快照可重新恢复
- 停站等待时原生 navigation.isActive() 为 false，运行器阶段为 POST_TRANSIT；到站身份仍只由 StationPresence 根据实际位置确认，不以“剩余距离为零”冒充到站
- 原生 ScheduleRuntime.getSchedule() 返回独立解析的查询副本，公开 paused、completed、currentEntry、state、currentTitle、conditionProgress 与 conditionContext。条件上下文不与正在执行的控制器共享；查询副本无法通过原生 returnSchedule 取走或复制驾驶台物品
- PhysicalNavigation 的 tick/startNavigation/cancelNavigation/read 与 PhysicalScheduleRuntime 的执行、设置、取回入口不会驱动第二套系统。原生 API 写入不会自动转发成驾驶台操作；仍从驾驶台操作时刻表
- 显式暂停、接管、取出、完成、改道、轨道失效、脱轨和编组不匹配会移除旧导航目标。驾驶台保有的时刻表及暂停进度仍可查询。移除代理时同时释放源计划缓存和两端查询状态
- 重进存档不持久化这一查询副本；先由原控制器恢复并重新规划，随后发布，避免把旧路由当作当前路线

两端 trains 命令补充状态、项目进度、目的地、剩余距离与后续轨段数，便于对照。没有新实体或额外物理体。计划与轨段未变化时复用源数据；查询解析仅在时刻表数据变化时重建。

0.2.16 本身不发布班次预测。0.2.17 在其查询接口上增加当前已确认目的站的原生显示数据，见下节。信号预约 UUID 及多站预测仍未接入。地图或铁路扩展是否读取这些接口仍需逐个验收，不能据此称为全部兼容。

## 0.2.17 原生车站信息显示

PhysicalScheduleRuntime.submitPredictions 返回原生 TrainDeparturePrediction，交给 GlobalTrainDisplayData 的正常刷新收集。原版 StationSummaryDisplaySource 通过 prepare 读取这些记录，因此无需额外显示板、显示链接或刷新 Mixin。原版约每 100 tick 刷新全局数据，本桥接不额外遍历全部列车。

每列仅发布当前已确认目的站的一条记录，携带代理列车身份、实际站名、行程标题和预计到站 tick 数。自定义标题直接使用玩家文本；空标题沿用 Create 的下一目的地筛选文本作为候补。没有确认路线的后续项目不生成预测，循环时刻表不会因此重复发布同一列的多条记录。

ArrivalEstimate 每五 tick 读取实际剩余路程与物理车体速度，以至少 20 tick 的连续前进记录建立估算，再用约两秒的平滑时间更新。它不读取轮子 RPM，也不使用原版列车的默认最高速度代替物理列车速度。倒计时是游戏 tick 的近似到站时间，不是承诺的实际耗时。

- 开始采样、停车、前进记录不足、等信号、等对接和无动力时使用原版 -1 待定标记，仍可显示已确认目的站
- 改道、下一站、部分卸载、重进存档、向目的地反方向移动或明显位置跳变会丢弃旧估算；不保存一个可能失效的历史倒计时
- 预计值始终至少为 1，剩余距离为零不能自行宣告到站。仅当运行器已进入等待阶段，且 getCurrentStation/getPresentTrain 双方确认为同一列车时发布 0
- 暂停、接管、完成、取出时刻表、脱轨或缺少有效铁路图时不发布预测；仍按原生显示刷新周期更新列表
- 到站等待只发布本站记录，不估算尚未满足的货物、红石、旅客等条件的剩余等待时间，也不猜测下一段路线

两端 trains 命令追加可用的预计秒数或待定状态，用于和原版显示板对照。此处不增加寻路、预约、牵引、制动、时刻表推进或物品交换行为。

## 0.2.18 驾驶台列车名称

驾驶台设置右上角增加列车名称按钮，打开同一菜单内的名称页。输入后点击“应用名称”或按回车保存；输入时库存快捷键作为文字处理，Esc 先返回设置主页。未应用的草稿不写入服务端，改名不退出接管或暂停时刻表。留空恢复带身份短 UUID 的默认名称。

主驾驶台在其方块实体 TrainName 字段保存纯文本。服务端重新验证当前打开的菜单编号、可达距离、玩家建造与交互权限、当前主控选举和操作员占用。备用驾驶台只读显示整列生效的名称，不能改写主驾驶台。服务端独立规范化为单行文本，限制为 64 个 UTF-16 单元；截断不拆开补充字符的代理项，过滤控制字符和颜色格式引导符。

连挂后采用现有主控规则选出的最早驾驶台名称，不合并名称或改写备用驾驶台自己的保存值。解挂、拆除主驾驶台或更换主控后，按新的主驾驶台重新发布名称；没有自定义值时使用默认名称。名称不改变稳定列车 UUID。

服务端与客户端的同一原生 Train.name 从身份快照更新，车站、显示板和两端查询共用该组件。保存后等待正常代理与原版显示刷新即可更新。重进时从驾驶台 NBT 恢复，不依赖原生 RailwaySavedData 保存代理，也不持久化第二份列车名称记录。

名称请求有独立结果回复，只有确认应用后页面显示“名称已保存”；等待回复时禁止继续编辑同一字段，避免晚到确认覆盖后续输入。输入草稿不会被菜单的周期同步覆盖。菜单数据增加名称字段，因此驾驶台网络协议从 2 更新为 3，客户端与服务端均需更新。

## 0.2.19 所有者信息

玩家新放置驾驶台时，在方块实体中保存 PlacedBy UUID 与 PlacedByName 玩家档案名。记录只由服务端放置回调生成，改名、接管、设置档位、装入时刻表或重新加载不会将当前操作员写成所有者。指令生成、没有玩家的放置及旧存档中缺少该记录的驾驶台保持未记录，不猜测历史放置者。

连挂编组与名称一样采用当前主驾驶台的记录，备用驾驶台页面显示整列生效的信息；解挂或更换主控后重新从对应驾驶台读取。UUID 是所有者身份，保存的玩家名只作为离线时也可显示的标签。没有新增玩家档案网络查询，也不把显示名当作身份键。

原生 Train.owner 字段与两端快照同步，缺少记录时使用 Create 原生支持的 null，替代早期查询代理使用的零 UUID。原生 Train.getOwner(level) 可按 UUID 查询在线玩家；玩家离线时返回 null 是原版行为，不会抹掉保存的 UUID。名称页增加所有者行和完整 UUID 悬停，两端 trains 查询也显示这两项。数据来自服务端只读菜单状态，没有增加客户端登记或转移所有者的写入包。

这一步提供放置来源与原生查询信息，不建立新的驾驶、改名或物品操作权限规则，不意味着已实现原版列车编辑和权限系统。驾驶台菜单增加可选所有者数据，协议更新为 4；客户端与服务端均需使用本版本。所有者保存在驾驶台，而非代理 SavedData，拆分、重进和部分加载仍由已有身份与主控恢复流程决定何时发布。

## 0.2.20 原生货物只读查询

每个逻辑 Carriage 的 storage 改为 PhysicalCargoManager，服务端将该车厢对应的物理车体绑定到现有 CargoStorage 快照。getAllItems/getMountedItems/getFluids 返回该车厢的槽位、储罐、内容和容量，内容返回副本；遍历全列车厢可得到整列货物。一个车体有多个转向架仍只有一份库存，多方块容器控制器和共享处理器沿用现有去重，连接器只计车上本地库存，避免将地面库存算作列车载货。

查询复用最多 20 tick 的快照缓存，每车厢同 tick 复用已解析视图；注册和运动快照不主动扫描库存。缺少车厢、容器未加载或原有货运扫描不完整时不发布部分数据；无法读取新容量元数据时仅使本车厢原生视图不可用，不改变原有物品数量条件和包裹运输的判断。getVersion 反映已观察到的内容、容量、可用性及输送记录变化。getTicksSinceLastExchange 仅在现有输送监测有效时提供空闲 tick，监测不可用时保守返回零。

这是服务端批量查询接口，未创建原版 MountedItemStorage 条目，getAllItemStorages 仍为空。燃料查询为空，原版燃料燃烧不参与牵引。插入、提取、灌入、抽取及模拟操作均拒绝，不复制存档库存，不执行原版卸载归还或可移式接口交换；装卸继续由实际物理容器和已支持的连接器负责。因此读取批量 handler 的扩展可以访问数据，但依赖原版挂载条目、容器交互或可写存储的扩展仍需单独适配。

客户端不接收整列物品和流体列表，其代理存储保持未绑定的空查询视图，不能据此判断列车实际空载。服务端可用 PhysicalTrainProxy.cargoReady 判断可用性；/physicalrailways cargo 命令读取实际原生 handler 并汇总数量，未就绪时明确提示，避免把未加载误报为空载。命令需要管理员权限，普通 trains 位置查询不会触发库存扫描。

拆分、合并、车厢款式变化、代理移除和世界卸载时解除旧绑定，释放世界、编组和库存快照引用；新绑定重新获取现有货运数据。没有新增实体、物理体或物品同步包。

离线检查覆盖实际原生管理器初始化、空查询接口、解绑版本变化、完整 handler 覆盖、读出副本和禁用写入路径。完整 ItemStack/FluidStack 的内容读取需要 NeoForge 注册表，未在普通 JVM 中伪造注册环境；非空库存、输送和重载需按下面场景人工验收。

## 0.2.21 列车观察器货物过滤与身份

PhysicalSignals 将每个编组的观察器上下文与原有信号区段集合一起沿轴端扫过、车厢覆盖和车端伸出范围传递，避免在检测点丢失所属编组。信号区段的占用、寻路和伸出边界算法不变；观察器仍只检查实际覆盖轨段的点，不向所有可能岔路触发。

无过滤的观察器保持基础检测。具有有效原生代理时调用 Create 的 TrackObserver.keepAlive(train)，让原生激活计时器与 currentTrain UUID 一起更新；无驾驶台结构不生成列车身份，仍只能提供无过滤脉冲，也不续期其他原生列车残留的身份。只提供身份查询入口，不据此宣称已适配所有显示链接或 ComputerCraft 事件。

有过滤时要求整列货物视图可用，从原生只读物品/流体 handler 取得非空内容副本，交给 Create 原版 FilterItemStack.test 判断。任意一个物品槽或储罐匹配即可触发，范围为整列，支持普通物品与 Create 过滤器已有的规则；不会执行或模拟提取，也不改变真实库存。卸载或货物未知时保守不匹配，已有脉冲按 Create 计时器自然结束。

每列使用完整且有序的各车厢货物版本列表缓存过滤结果，避免每个轮轴、每个 tick 重复遍历整列货物。过滤对象更换、版本变化、可用性丢失、车厢重建及代理移除时失效；过滤项缓存上限为 256，防止频繁更换配置长期积累。库存更新仍受现有最多 20 tick 的扫描缓存影响。

离线检查覆盖缓存命中、车厢版本顺序变化（含相同总和）、过滤器更换、未知/恢复、解绑清理、缓存上限及观察器只读调用边界；实际过滤匹配、红石输出和 UUID 关联仍需游戏内验收。

## 0.2.23 服务端信号区段身份

PhysicalSignals 的区段覆盖与短期预约仍是物理列车的唯一信号依据。每个服务端 tick 结束时，在原生身份注册更新之后，将有效且编组恢复完整的代理与内部物理占用者关联：SignalEdgeGroup.trains 包含已有的同一 PhysicalTrainProxy，Train.occupiedSignalBlocks 的键为实际覆盖的区段，Train.reservedSignalBlocks 是物理后端已有的未来预约区段。没有驾驶台的结构不创建身份，继续通过物理占用检查阻挡其他列车。

Create 在其 tick 中清空区段列车集合，随后统一调用各列车 earlyTick。本代理的 earlyTick 只重新发布已有的区段查询关联，不执行原生 Train.earlyTick、导航、运行器或物理推进。轨道区段对象被替换后不再向旧对象重发，后续物理刷新采用新注册表。正常运动与尾部释放沿用原有覆盖算法，发布阶段不重新寻路或扫描铁路图。

原有 Mixin 的 Train 排除查询改为识别已注册代理对应的物理占用者，只排除自身；同区段第二列物理列车、没有身份的结构及其他列车的预约仍阻挡查询。物理列车申请信号时，原生集合中的物理代理不再次参与判断，因为它们已由物理账本统一检查；真正原版列车和原生保留信号仍参与阻挡，避免自身代理使自己停车。

查询投影不写 SignalEdgeGroup.reserved，也不启动原生预约控制器。原生设备通过现有物理占用 Mixin 继续感知短期预约；直接读取区段列车集合只表示实际占用，不能把所有未来预约看作车体已经驶入。occupiedSignalBlocks 的值保留 null，表示本后端没有原版边界穿越历史，不伪造一个不存在的入口信号 UUID。

每次更新仅移除本代理上次发布的成员，保留同区段其他列车；合并、拆分、控制台移除、代理注销及世界卸载会清除旧身份关联和原生查询字段，实际仍在轨道上的物理占用由物理账本保留。查询状态不写进 SavedData，重进后由加载完整的物理编组重建。

本轮仅发布服务端区段身份。客户端查询未增加占用/预约数据包，不能据此宣称客户端铁路地图已完成信号身份适配。服务端 /physicalrailways trains 追加原生占用与预约区段数，客户端不把缺失的数据显示成零。查询计数可能包含车体伸出或交叉冲突的保守覆盖，不表示轮轴所在区段数量。

离线检查覆盖占用者自身排除、同区段多列车、长车尾部覆盖、未来预约归属、暂停/成员变化清理，以及 earlyTick 只发布、不写原生预约、精确移除自身的字节码边界。实际信号刷新时序、混跑及 Mixin 应用仍待下列游戏内验收。

## 0.2.24 客户端信号数据同步

占用或预约区段集合变化时，服务端发送 SignalOnly 独立快照，携带列车 UUID、维度、递增版本、是否已知及两组区段 UUID。正常身份/位置快照不重复附带完整区段列表，短期预约续期但区段未变时不重新发送。首次登录在身份快照之后补发当前信号快照；协议从 1 更新为 2，客户端和服务端需一起更新。

客户端只更新已有 PhysicalTrainProxy，不以信号包单独创建列车。先到的信号快照在有上限、有限寿命的等待队列中暂存，等待对应身份。身份存在但铁路图尚未同步时，代理保留最新期望 UUID，不发布部分占用。每客户端 tick 只检查这些 UUID 是否可解析，加载齐后自动恢复，重复快照和更旧版本不覆盖更新状态。

服务端与客户端共用 NativeSignalState 投影器，但分别绑定各自的区段与列车注册表，客户端不会把代理写入 Create.RAILWAYS。原生占用和预约字段、两端 trains 查询中的计数可互相对照。已解析区段对象被替换或移除后，撤销旧对象上的自身记录，并等待新对象可用；不会清除同区段其他列车。

注销包清除等待数据、原生字段及旧区段成员；断线清理所有物理代理的查询状态。列车维度信息变化时先清除旧信号视图，再接受匹配新维度的快照；玩家切换维度不把仍存在于其他维度的全局列车身份当作已删除。正常位置快照不会清掉已收到的信号视图。

UUID 数组有长度与结构验证，每组最多 4096 项。超出发送范围时保守使用未知状态，不因构造超大数据包崩溃；物理后端信号账本仍负责实际阻挡。客户端未就绪时不把缺失区段显示为已确认的零占用。没有传输铁路图、物品内容或任何驾驶写入权限。

离线检查覆盖实际网络编码、已知/未知/空集合、格式错误、不可变快照、铁路图不完整与恢复规则、客户端注册表隔离及生命周期入口；不等于已验证客户端网络时序或第三方地图集成。

完成同步后检查了 197 个项目 Java 源文件的引用与相关历史入口：删除无运行时调用的 TrackNetwork.steerBranch、BranchSelect.fromHeading/steer 及只覆盖这些旧入口的测试，改测当前 choose 算法；合并客户端注销/断线的释放路径，移除重复的 ready 状态字段，避免每次发布都重复复制两组 UUID。铁路图缺失区段保持未知，注销包即使在客户端世界尚未就绪时也清除等待数据。此检查不宣称已自动证明全项目不存在任何冗余，反射、Mixin 和公开扩展接口未按文本引用次数盲删

## 人工测试步骤

1. 放一副转向架，无驾驶台时执行 /physicalrailways trains，不应出现新列车；安装驾驶台后出现一列，同车体加第二副仍是一列
2. 客户端执行 /physicalrailways_client trains，服务端与客户端 UUID、车厢数和位置应该一致
3. 新建第二车体并连挂，变一列两车厢；解挂后只有有驾驶台的分组注册，两边都有驾驶台时才是两列，UUID 不重复
4. 退出接管、停车、断电后仍保留列车；拆掉最后一个驾驶台后两端查询中消失，重新安装后恢复。行驶、反向、弯道以及脱轨后查询，位置与速度对应实际车体，未关联轨道时不虚构正常沿轨行驶
5. 退出重进，UUID 保持，世界中没有重复车厢；等待车钩恢复后仍是一列
6. 卸载部分车厢后返回，恢复原身份，不产生新的尾车身份；拆除全部转向架后不留下活动代理
7. 混跑原版列车，原版行驶、保存和登录显示正常，碰撞表现不受代理重复影响
8. 检查 Xaero 菜单可以打开、地形/实体雷达可用；将它与上面的原生注册表查询分开验收
9. 手动与时刻表两种方式进站停稳，车站旗帜、比较器、列车名称和两端查询中的站名一致；高速通过不宣告到站
10. 在站内退出接管、切换方向或暂停时刻表，仍维持停靠；驶离、用手杖移走、拆驾驶台或车站后清理站名与到站信号
11. 站内退出重进、车厢延迟加载和站内解挂后没有幽灵占用；一个编组不同时占用重叠的两个车站
12. 有原版列车预约或停靠时，物理列车不覆盖该预约；释放后才能建立自己的关联
13. 回归铁路对接连接器与包裹取送，不能把自己的原生到站身份误判成另一列车占用
14. 车站存放自动时刻表时不启动代理原生运行器，仍通过物理驾驶台管理时刻表；不允许原版组装拆车
15. 装入有效时刻表，执行两端 trains 命令，比较目的地、进度和剩余距离；正常行驶时剩余距离递减，反向运行、进出岔路后路线方向一致
16. 停站等待时车站关联保留，查询中的行程转为等待；条件满足只推进一次项目，随后发布下一站
17. 暂停、手动接管和取出时刻表，旧导航目标与后续轨段应清空；暂停保留项目进度，取出后不再显示时刻表
18. 删除前方轨道、改站名、改道、解挂或拆除驾驶台，不能继续报告旧的有效路线；恢复后仅采用重新确认的计划
19. 行驶或等待时退出重进，对照驾驶台与两端查询；客户端铁路图稍晚加载时最终恢复一致，不生成另一套时刻表物品或车厢
20. 用原版车站、显示链接与显示板配置车站信息，装入有效时刻表；允许原版显示刷新约五秒，检查当前目标站出现本列名称与行程标题，连续行驶后可读取近似到站时间
21. 等信号、断动力、停车或等待对接时，到站时间应为待定；恢复行驶后重新建立估算。暂停、取出和完成后对应记录在正常刷新后消失
22. 到站并设置足够长的等待条件，对照车站旗帜、比较器和显示记录；只在真实停稳后发布到站，不因剩余距离接近零而提前确认
23. 测试循环时刻表、反向、改道、手杖移动车体和退出重进，不能复用错误倒计时或生成重复记录；混跑原版列车时其显示信息不受影响
24. 从驾驶台名称页输入中文、英文及长名称后应用，关闭重开、退出重进，比较两端 trains 查询、车站与原版显示板；输入字母 E 不应关闭名称页
25. 清空并应用恢复默认名称；仅修改草稿后退出，不应改名。自动驾驶期间改名，牵引、时刻表项目和等待进度保持原运行逻辑
26. 两列分别命名后连挂，只显示主驾驶台名称，备用页只读；解挂后各自恢复本驾驶台名称，拆除主驾驶台后按新的主控更新
27. 另一玩家占用、无建造权限、菜单过期或远离驾驶台时无法改名；页面不能把未成功写入显示成已保存。中英文与 GUI 缩放下检查按钮、输入焦点、横向滚动与长名称悬停
28. 新放驾驶台后打开名称页和两端列车查询，对照实际放置玩家及 UUID；关闭重开、退出重进后记录保持。旧驾驶台或指令生成的驾驶台应显示未记录
29. 由不同玩家放置并命名两列后连挂，核对生效名称和所有者均来自同一主驾驶台；备用页只读显示整列信息，解挂后各自恢复自己的记录
30. 切换驾驶员、改名和自动运行不得改变放置者记录或额外限制原有驾驶操作；所有者离线时仍可查看记录，原生在线玩家查找按其原有规则返回
31. 在列车上放入已知数量物品和流体，执行 /physicalrailways cargo，核对总数、槽位和储罐数；同一车体增加转向架不得重复计数，真正空载应显示零
32. 连挂两车、使用多方块容器并连接地面装卸设施，核对各车厢合计；地面库存和同一容器控制器不得重复计入，实际输送后允许约一秒缓存更新
33. 解挂、移除驾驶台、退出重进及部分车厢延迟加载后查询，不得保留旧编组库存或将未加载显示为空载；回归原有数量条件、装卸空闲和包裹任务
34. 设置普通物品过滤与 Create 过滤器，分别用匹配、不匹配和空载列车通过观察器；连挂尾车装有匹配货物时也应触发，清空后允许约一秒库存刷新再加原生脉冲衰减
35. 用流体过滤检查多个储罐中的匹配内容，停在观察器上增减货物、更换过滤器、卸载恢复，输出应随有效内容变化，不能因只读存储无法模拟抽取而始终不触发
36. 用原生观察器信息读取接口核对 currentTrain 与 /physicalrailways trains 的 UUID；前进、倒退、高速通过、连挂和拆驾驶台后不残留永久激活或假身份。混跑原版列车及无驾驶台结构时回归无过滤检测
37. 在两个信号区段之间停车，服务端 trains 查询仍是同一 UUID，并显示占用区段数；车头进入下一段而尾部尚未清空时，后方区段不得提前释放
38. 单物理列车自动运行、停车、恢复和倒车，不因自己的区段身份或未来预约卡住；两列物理列车同区段或相向请求时不能因自身排除而互相放行
39. 物理列车与原版列车双向追踪、会车及交叉混跑：原版占用和预约仍阻挡物理列车，物理占用和预约仍阻挡原版列车；退出冲突范围后正常恢复
40. 普通信号与链式信号连续组合，检查停止范围、保留出口及恢复；暂停或接管后未来预约释放，但停车车体覆盖不能消失
41. 连挂、解挂、拆除驾驶台以及轨道/信号重建后不残留旧代理；没有驾驶台的结构仍阻挡信号，但不凭空出现原生列车身份
42. 长列部分卸载、返回、世界卸载及退出重进，编组与原生身份恢复后重建区段关联；同区段另一列原版或物理列车的记录不能被本列清理掉
43. 比较 /physicalrailways trains 与 /physicalrailways_client trains 的占用、预约计数；直行、停车和跨信号时最终一致，停车且区段不变时不会每 tick 重发完整列表
44. 加入已有运行列车的服务器、退出重进和铁路图延迟加载，身份与信号包无论先后最终都能恢复；加载不完整时不显示虚假的部分区段数
45. 重建信号区段、解挂、注销与断线后旧对象记录清除，同区段另一列的记录仍保留；切换玩家维度后检查全局列车查询，不能将其他维度列车误当已删除
46. 世界加载或切换期间收到注销后不恢复幽灵列车；断开并加入另一存档/服务器，旧停靠关联、信号区段与等待队列不串到新连接。回归左右选岔、默认小角度、反向滑行及连挂跟随路线

最后集中验收时，也需执行 [货运访问边界清单](CARGO_ACCESS_BOUNDARY.md)，特别是实际对接期间的信号等待和发车恢复

服务端查询需要管理员权限；客户端查询只读取本机收到的原生注册表。两者输出已本地化。
