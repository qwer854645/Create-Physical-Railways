# 原生列车身份与车站关联

适用：0.2.15 · Create 6.0.10 · Minecraft 1.21.1 / NeoForge

## 已实现的范围

每个已加载、连挂恢复完整且包含有效主驾驶台的线性物理编组，在 Create.RAILWAYS.trains 中注册一个 PhysicalTrainProxy（Train 子类）。客户端在 CreateClient.RAILWAYS.trains 中保持同类代理。

- 有效主驾驶台由现有编组主控选举确定；不要求玩家正在接管，不要求通电，也不要求时刻表正在运行
- 整列只需一个驾驶台，无驾驶台的挂车连入后属于同一列车；拆掉最后一个驾驶台后撤销服务端与客户端活动注册
- 从未安装驾驶台的散装转向架不分配列车身份；已注册列车暂时移除驾驶台时可保留休眠身份，重新安装后恢复
- 稳定 UUID 独立于驾驶台，成员按转向架物理体 UUID 保存
- 连挂合并保留一个已有身份，另一身份退役；解挂后包含身份锚点的一组保留 UUID，其他组创建新 UUID
- 身份锚点被确认删除时，剩余成员接替锚点；卸载不等于删除
- 数据保存在当前维度的 guidedrailways_trains SavedData 中
- 已知成员尚未恢复、或保存的车钩尚未恢复时，暂不发布这一编组，避免错误拆成多列车
- 每个物理车体对应一个逻辑 Carriage，同体多转向架使用首尾转向架描述原生车厢，中间支承仍由物理系统处理
- 提供默认名称、UUID、车厢位置、维度、实际速度、轨道关联和保守长度估算
- 速度转换：物理后端格/秒除以 20，转换为 Create 的格/tick
- 五 tick 刷新服务端代理，十 tick 同步客户端；新建、移除和玩家登录额外同步
- 没有新增世界实体、物理体、碰撞箱或可见车厢

原生车厢间距与转向架间距是整数，本阶段做取整表达；列车长度按物理体世界包围盒和车体间隙保守估算。它们仅用于查询，不参与牵引、车钩或碰撞求解。

## 隔离边界

代理 earlyTick/tick 不执行原版运动、时刻表或信号更新；逻辑车厢不生成实体。原版拆车入口对代理返回不可拆。代理的 arriveAt/setCurrentStation/leaveStation 入口仍不执行原版副作用；实际关联仅由经过停稳验证的车站桥接更新。

三处定点 Mixin 只过滤 PhysicalTrainProxy，原版列车保持原路径：

1. 原版登录 AddTrainPacket：代理使用自定义快照，避免客户端被解码成普通 Train
2. RailwaySavedData.save：代理不保存为普通列车，避免重进后由 Create 生成重复车厢
3. Train.findCollidingTrain：避免代理触发第二套原版列车碰撞；原有 Sable 接触兼容保持不变

用户要求保留的单轨回调检查完全不变。

## 0.2.15 原生车站关联

沿用现有轨道方向、头部位置与停稳检测：距停靠点不超过 0.25 格、速度不超过 0.12 格/秒连续六 tick 后确认；已到站后允许小幅物理抖动，偏离超过 0.5 格或速度超过 0.2 格/秒即离站。高速经过、反方向车站、组装中的车站、脱轨和未完整恢复的编组不建立关联。停靠期间锁定到达时的物理轮轴参考，原地切换方向或驾驶员不应因“车头”改到另一端而错误离站。

关联通过 GlobalStation.reserveFor(proxy) 和代理 currentStation 建立，满足原生 GlobalStation.getPresentTrain()/getImminentTrain() 的双向验证。不会调用 Train.arriveAt()，避免提前推进原版时刻表或触发原版邮箱交换。其他原版列车或非本桥接持有的预约不会被覆盖；重叠车站和多个物理列车采用稳定的单站单车选择。

已删除 GuidedPhysicalPresent 客户端标记与 StationBlockMixin 比较器覆盖。旗帜、原生到站 UUID、列车名称展示及比较器改由 StationBlockEntity 原生 tick 驱动。原生车站计算机事件现在有条件沿此入口识别代理，但未做外部计算机模组的客户端验收，也不代表其全部列车 API 均已兼容。

离站、移动车体、拆除最后一个驾驶台、编组改变、车站删除、代理移除或世界卸载时解除旧关联。取消预约只作用于本代理，不清除其他列车预约。重新进入存档后根据实际位置重新确认，不保存一个可能失真的到站占用。

客户端快照携带车站 UUID，在客户端原生轨道图就绪后建立查询关联。现有身份查询命令增加“车站”字段，仅在 getCurrentStation 与 getPresentTrain 均匹配时显示站名。

物理列车的时刻表仍存放在驾驶台，原生车站的自动发放和取回时刻表入口对代理保持隔离，避免给空的原版运行器发放任务或取走错误物品。物理包裹取送接受本站为当前列车自身占用，其他列车占用时仍等待。

## 本阶段未迁移的功能

现有驾驶台、时刻表执行器、停稳检测、导航、信号占用和物理碰撞仍由原系统负责；停稳结果现在驱动真实原生车站关联。代理暂不发布原生 Navigation 目的地、ScheduleRuntime 进度、真实所有者、货物和旅客视图，也不提供完整列车编辑功能。默认名称用于识别，原版名称编辑的持久化尚未接入。

环形或分支车钩网络、没有转向架的独立中间车体暂不发布代理。多副转向架不会因此新增原版车厢实体。跨维度行驶不在本阶段范围。

## Xaero 测试环境

安装的可选开发模组：Xaero's Minimap 26.6.0，NeoForge / Minecraft 1.21.1。官方文件 URL 和 SHA-256 见 verification/map-test-dependencies.json。

准备环境：

    python verification/prepare_dependencies.py --with-map
    gradlew.bat copyDevMods --offline

Xaero 仅用于开发环境，不打入本模组 jar，也不是运行依赖。该版本的类文件未发现直接访问 Create 列车类/注册表的引用，其官方介绍的雷达主要面向实体。因此不能用“Xaero 显示/不显示列车”作为原生身份桥接成败的唯一标准。本阶段没有额外伪造实体或地图路径点。

## 人工测试步骤

1. 放一副转向架，无驾驶台时执行 /physicalrailways trains，不应出现新列车；安装驾驶台后出现一列，同车体加第二副仍是一列
2. 客户端执行 /physicalrailways_client trains，服务端与客户端 UUID、车厢数和位置应该一致
3. 新建第二车体并连挂，变一列两车厢；解挂后只有有驾驶台的分组注册，两边都有驾驶台时才是两列，UUID 不重复
4. 退出接管、停车、断电后仍保留列车；拆掉最后一个驾驶台后两端查询中消失，重新安装后恢复。行驶、反向、弯道以及脱轨后查询，位置与速度对应实际车体，未关联轨道时不虚构正常沿轨行驶
5. 退出重进，UUID 保持，世界中没有重复车厢；等待车钩恢复后仍是一列
6. 卸载部分车厢后返回，恢复原身份，不产生新的尾车身份；拆除全部转向架后不留下活动代理
7. 混跑原版列车，原版行驶、保存和登录显示正常，碰撞表现不受代理重复影响
8. 检查 Xaero 菜单可以打开、地形/实体雷达可用；将它与上面的原生注册表查询分开验收
9. 手动与时刻表两种方式进站停稳，车站旗帜、比较器、列车名称和两端查询中的站名一致；高速通过不宣告到站
10. 在站内退出接管、切换方向或暂停时刻表，仍维持停靠；驶离、用手杖移走、拆驾驶台或车站后清理站名与到站信号
11. 站内退出重进、车厢延迟加载和站内解挂后没有幽灵占用；一个编组不同时占用重叠的两个车站
12. 有原版列车预约或停靠时，物理列车不覆盖该预约；释放后才能建立自己的关联
13. 回归铁路对接连接器与包裹取送，不能把自己的原生到站身份误判成另一列车占用
14. 车站存放自动时刻表时不启动代理原生运行器，仍通过物理驾驶台管理时刻表；不允许原版组装拆车

服务端查询需要管理员权限；客户端查询只读取本机收到的原生注册表。两者输出已本地化。

## 验证边界

离线检查覆盖身份合并/拆分/重载/部分卸载、车站单车互斥及外部预约保护、真实 NBT 二进制往返、代理空操作字节码与原生车站接口及注入位置。不能脱离 NeoForge 加载环境实例化完整原生列车，因此这些检查不能代替 Mixin 应用、物理车厢映射与客户端同步的游戏内验收。本次不自行启动客户端或服务器。
