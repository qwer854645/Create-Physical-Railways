# 机械动力铁路兼容范围

更新日期：2026-10-21 · 当前版本：0.2.24 · 参考依赖：Create 6.0.10-280 / Minecraft 1.21.1

## 当前结论

尚未达到“完全兼容机械动力铁路系统”的目标。物理列车使用独立物理驱动与时刻表执行器，并以只读原生 Train 身份向 Create 设备提供数据。查询桥接不会启动第二套原生导航、库存或驾驶逻辑。

历史问题与改动过程见 DEVELOPMENT.md 和各专题文档；本文件描述当前实现，不将旧版本的待办当作现状。用户已反馈本轮其他验收项目通过，信号另有有限范围的服务端验证；这不等于所有布局和所有第三方模组均已验收。

## 已接入的功能

### 轨道与驾驶

TrackNetwork 读取原生轨道图，支持同维度直轨、弯轨、坡道及分岔。ConsistRoutes / RouteMemory 保存整列的岔路通过记录，后轴和后车跟随头车，手动倒车可回溯。自动寻路由 AutomaticNavigation / ScheduleRoute 负责。实际动力、制动、转向架关节与碰撞仍由物理后端负责。

### 原生列车身份、车站与显示

只有存在有效主驾驶台的受支持编组发布原生 Train 代理；列车名称由驾驶台管理，所有者取自主驾驶台放置记录。身份、逻辑车厢、位置、速度、停靠车站、导航目的地、行程进度、时刻表状态和当前目的站预计到达信息已接入服务端与客户端查询。

StationPresence 根据实际停稳位置关联 GlobalStation，旗帜和比较器由原生车站更新。列车未实际停靠时，不以计划目的站冒充当前车站。

重进或区块重载后，从停稳列车两端的实际轨道位置重新确认停靠，不依赖换向档位或缓存的到站标志。已停靠时固定到站端，换向不会制造虚假离站；客户端在轨道图迟到、分批同步或重建后重试查询与车站关联。

车站界面中的物理列车名称只读并随驾驶台更新，名称仍在驾驶台编辑。原版名称 / 图标 / 地图颜色编辑包不会改写物理代理；原生列车不受此限制。车站的物理列车组装与拆解入口均受服务端保护，界面显示对应限制。时刻表交接不在本轮范围。

代理的原生导航、时刻表执行、库存挂载及组装入口受到隔离，避免外部调用驱动两套系统。查询兼容不代表原版列车编辑界面的写操作或任意 ComputerCraft 控制调用都受支持。

详见 [原生身份桥接](NATIVE_TRAIN_IDENTITY.md)。

### 时刻表

支持在驾驶台装入、取回、查看原版时刻表，以及暂停、继续、跳过和重新开始。

当前接受的指令：DestinationInstruction、ChangeThrottleInstruction、ChangeTitleInstruction、FetchPackagesInstruction、DeliverPackagesInstruction；包裹指令需要相应可选兼容可用。

当前接受的等待条件：ScheduledDelay、TimeOfDayCondition、StationPoweredCondition、RedstoneLinkCondition、ItemThresholdCondition、FluidThresholdCondition、IdleCargoCondition、PlayerPassengerCondition。

任务实际运行、等待进度和恢复由 ScheduleController 管理，原生 ScheduleRuntime 仅提供查询视图。时刻表物品仍实际存放在驾驶台；车站自动发放和取回入口当前保持隔离，不会把时刻表写入空的原生执行器。本项是当前明确的交互边界，不是应删除的旧实现。

### 信号与列车观察器

PhysicalSignals 负责真实物理编组的区段覆盖、保守车体延伸、交叉冲突和短期预约。原版列车与物理列车相互感知占用；自动驾驶按信号制动并恢复，手动驾驶上报占用但不强制红灯停车。

服务端与客户端均已同步原生占用 / 预约查询身份。客户端等待铁路图完整后解析，处理注销、断线及区段替换；不能再描述为“客户端信号身份尚未同步”。

观察器支持物品 / 流体过滤，并关联已有列车 UUID。货物未知时不伪报匹配，车体端部延伸不向所有岔路触发观察器。复杂布局仍需对应验收。

低速直轨、单车厢、普通信号下，两种前后车组合已完成真实车辆停车、车尾清空和恢复通行测试；同时通过 14 项信号接口断言。详见 [服务端信号验证](SIGNAL_SERVER_VALIDATION.md)。链式信号、交叉、高速、长列与重载恢复不能据此视为全部通过。

### 货物、流体、包裹与旅客

整列统计复用实际物理车体容器；原生车厢提供只读货物视图，不复制挂载库存，也不将整个编组变成一个可随意抽取的库存。实际输送仍受具体物理连接器及其对接范围限制。

已接入整列物品 / 流体数量条件、限定输送路径的装卸空闲、Create 座椅玩家乘客条件，以及通过铁路对接连接器完成的包裹取送。可选兼容包括 Hose Connectors、Simulated 对接连接器和 Automated Logistics。

详见 [货运](CARGO_COMPATIBILITY.md)、[货运访问边界](CARGO_ACCESS_BOUNDARY.md)、[旅客](PASSENGER_COMPATIBILITY.md)、[包裹](PACKAGE_COMPATIBILITY.md) 和 [铁路对接](RAIL_DOCKING.md)。这些适配不代表原版可移式接口可直接装卸 Sable 车体。

## 仍未实现或不在当前范围

- 跨维度整列迁移：导航跳过跨维度边，车钩在跨维度移动时解挂
- StationUnloadedCondition 等当前白名单以外的时刻表内容
- 任意原版列车编辑 / 控制写入口，以及所有第三方铁路、地图和 ComputerCraft 集成
- 原版可移式接口直接装卸物理容器、离线邮箱写入及跨维度旅客迁移
- 拥堵绕行、预约公平队列与通用死锁恢复
- 环形 / 分支车钩网络等原生身份桥接尚不支持的编组，边界见原生身份文档

## 后续工作边界

本轮停止扩展信号测试，优先清理迁移后残留的旧代码。后续功能应围绕具体使用场景决定，不为补齐原版入口而加入不自然的远程物品传送，也不以只读身份桥接替换现有物理容器访问边界。

只有约定范围内的功能有明确实现、对应验收完成且阻断问题关闭后，才可使用“完全兼容”的表述。
