## 本次实现

### 整列存储

`CargoStorage` 沿车钩编组收集车体，包括没有转向架的拖行车体。同一车体的多个转向架只产生一份存储统计，Create 仓库和储罐按控制器去重。支持读取普通容器与 NeoForge 物品/流体能力接口。

读取现有存储，不重新组装箱子、不复制回写库存、不提供新的输送设备。原版双箱按每个方块自身的槽位读取，避免把两半的合并能力重复统计。对于方向限定、代理或远程存储，不保证第一个公开能力视图就覆盖全部存储；这类第三方容器需单独验收。

软管读取自身库存和储罐。对接连接器通过公开字段读取本端 inventory/tank，不调用会返回双方组合库存的 getInventory，也不把站台对端的箱子、水箱当作车载货物。

数量快照最多缓存 20 tick，每个编组共享一份。载入时包含仍以 NBT 保存、尚未实例化的方块实体；不为统计强制加载世界区块。存在未恢复的车钩连接、缺失的方块实体或兼容 API 异常时，不把缺失数据视为空库存。运行时保存车体成员身份，裸车厢的丢失不会被转向架数量检查漏过。

### 原版时刻表

新增支持 ItemThresholdCondition、FluidThresholdCondition 和 IdleCargoCondition，继续使用 Create 原版时刻表编辑器和过滤器。

- 物品按个数或完整堆叠槽位计数；例如分开的 63 个和 1 个普通物品，不会被当作一个完整堆叠槽
- 流体以 mB 比较，再换算桶数阈值，不先对现有流体数量取整
- 大于、小于均为严格比较，另支持等于；汇总使用 long 避免普通 int 溢出
- 保持组内顺序、组间任选的等待规则
- 数量条件只读取实际内容，不调用需要原版 Train 的条件方法，也不伪造 Train

### 成功交换记录

`CargoTransfers` 仅为已登记存储记录活动。NeoForge ItemStackHandler/FluidTank 的成功插入、提取及直接设置内容路径可以记录活动；Simulated 的原生单槽库存、对接储罐另外接入成功返回值。模拟操作、零转移量不重置计时。同一刻中移出后又补回相同内容仍能记录交换。

Hose Connectors 通过原有缓冲区输送，不更改连接、流向、转速或容量规则。Simulated 储罐向对端插入时，活动同时归到连接双方，以覆盖站台向车体输送的路径。Automated Logistics 的本地缓冲交接也记录成功活动。

一般容器另做内容快照变化补查，但不声称能捕获任意模组绕过公开接口的修改，也不能保证发现轮询间隔内恢复原状的未知修改。精确空闲记录的承诺限于本次接入的输送路径。

装卸空闲要求编组中装有兼容的软管或对接连接器。未安装时显示“等待兼容的装卸接口”；检测到不匹配的连接器 API 时不把它当成可精确监听的接口。重载后重新观察空闲时间，不将离线时间算作无装卸。

### 对接发车

到站后可以在锁定对接期间执行货物等待条件。等待完成后，如果车体仍被编组外部的对接连接器锁住，自动驾驶显示“等待解除对接”并保持制动。使用原模组的红石或对接控制解除锁定后继续。

本模组不自动解开玩家的对接连接，也不把站台连接纳入车钩编组。

### Automated Logistics 的联动边界

其货物链接读取本列车上的容器时，按原先选择的物品/流体类型扩展到同一车钩编组。普通站台容器、非本模组车辆保持原来的选择范围；对接缓冲仍由 Automated Logistics 自身的独立阶段统计，避免额外扩展时重复添加。

对接快照附加交换版本标记，实物堆栈、流体内容、数量和容量均不改变。这样其停靠空闲检查也能看到本轮记录的成功交换，而不只比较最终物品数量。资料不完整时返回无可用货物快照，由其现有逻辑拒绝完成货物条件。

这属于货运和停靠数据兼容，不包含把本列车伪装为 Simurail、改写它的飞行路线回放、卸载行驶、地图身份或导航控制。列车沿轨运行仍使用我们的驾驶台与原版时刻表，不能据此宣称两套自动驾驶可以同时控制同一车体。

## 可选加载与验证

兼容 Mixin 使用软目标；可选模组不存在时跳过。启动插件检查已知目标方法的完整字节码签名，变化时禁用对应挂钩并记录日志。反射仅访问已核对的公开方法和字段，读取异常会使本次货物数据不可用。

已执行：离线构建、语言检查、货物活动与阈值回归检查，以及三个真实发布包的 36 项接口签名检查。签名检查不等于 Mixin 已成功应用，也不等于运输玩法通过。

运行签名检查：

```powershell
python verification/check_cargo_compat.py --hose <软管发布包> --simulated <从航空学提取的Simulated发布包> --logistics <物流发布包>
```

- Simulated 1.3.2：`fdf9d250996a084b52fced3a5b0089e879a5cac05dc7bcf295ac1f4ebe5e2bff`
- Automated Logistics 0.7.0：`a7f1519f19b54363de387381e0e37192e0a5929c5f72d8e778425c1a39496956`

## 待进行的客户端测试

1. 不安装软管和 Automated Logistics 时启动，确认可选目标缺失不导致启动失败；再装齐三个对应版本启动，检查 Mixin、能力读取和存档日志
2. 单车箱子、双箱、桶、潜影盒、Create 仓库和多方块储罐；同车体增加第二副转向架，确认总数不翻倍
3. 两辆连挂车及无转向架拖车分别装货，测试整列过滤、解挂后的成员检查、粘合及移动车体后的恢复
4. 手动/磁性物品软管双向装卸；停转或堵塞后空闲计时恢复，实际持续交换时不提前发车
5. 流体软管双向装卸，检查指定流体、1.5 桶与 1 桶等于条件、严格大于/小于与空罐条件
6. 对接连接器两端各留不同数量的货物与流体，确认本列车不把站台库存算进去；保持对接锁时不牵引，解除后继续
7. 同一刻向连接器移入并移出同样数量，检查装卸空闲不能提前完成；纯容量模拟和失败操作不延长等待
8. Automated Logistics 货物链接只选一节车的箱子/水箱，检查同类型存储是否扩展到整列，站台链接不扩展；检查原生缓冲统计与新增活动标记
9. 等待货物时退出重进、延迟恢复拖车或连接器，确认不误判为空；检查空闲计时重启及其他已完成等待条件的保持
10. 中英文状态与不同 GUI 缩放，确认新状态无翻译键泄露或溢出

本轮没有启动客户端或服务器；以上实际流程尚待验收
