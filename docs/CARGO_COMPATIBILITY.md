# 物理货运兼容

当前文档介绍实际车载存储统计与 Simulated 对接连接器的输送边界。统一规则和人工验收场景见[货运访问边界](CARGO_ACCESS_BOUNDARY.md)。

## 依赖与输送路径

核心环境为 Minecraft 1.21.1 / NeoForge / Create / Sable。可选对接功能使用 Create Aeronautics 捆绑的 Simulated 1.3.2；具体开发版本见[依赖说明](DEPENDENCIES.md)。

连接器与容器之间需要实际漏斗、传送带、管道等输送路径。连挂或粘合不使独立容器自动互通，也不会形成可写的整列仓库。

## 整列统计

`CargoStorage` 沿车钩编组收集真实车载容器，包括没有转向架的拖行车体。同一车体的多副转向架不重复计数，Create 仓库和储罐按控制器去重。支持普通容器与 NeoForge 物品、流体能力；方向限定或代理存储的覆盖范围需要单独验收。

Simulated 对接连接器只读取本端库存与储罐，不把站台对端内容当作车载货物。缺失车厢、待恢复连接、尚未加载的容器或兼容接口异常不会被当作空载。

## 时刻表与装卸活动

整列物品、流体数量和装卸空闲条件使用实际货物观测。数量条件保留原版比较规则和过滤器，装卸空闲以有效观测及真实成功交换计时。模拟查询、失败操作和零转移量不重置活动计时；重载或观察中断后重新计时，不把离线时间当作装卸空闲。

NeoForge 标准库存、储罐与 Simulated 对接缓冲的已接入成功交换路径可记录活动。其他容器的快照变化检查不能保证捕获绕过公开接口、在轮询间隔内恢复原状的修改。

到站等待条件可在对接锁定期间执行。条件完成后，外部锁仍未释放时列车保持制动；玩家须通过原有红石或对接控制解除外部锁。

## 包裹

铁路对接连接器的包裹交换需要有效车站绑定、当前控制器的对接请求、互相配对和双端锁定。实际交换只使用对应缓冲及车站关联邮箱，不直接访问整列任意箱子。

已加载且关联有效的邮箱交换可为本次停站提供真实活动记录；未加载邮箱不会被当作实时交换端。详见[包裹运输](PACKAGE_COMPATIBILITY.md)与[铁路对接](RAIL_DOCKING.md)。

## 验证

可选接口使用软目标，依赖缺失时跳过；已知方法签名不匹配时禁用对应挂钩。签名检查不代表真实 Mixin 应用或装卸玩法通过。

```powershell
python verification/check_cargo_compat.py --simulated build/compat-api/simulated-neoforge-1.21.1-1.3.2.jar
```

待实机验收：多车统计去重、未知容器恢复、物品和流体双向输送、满仓与堵塞、真实交换的空闲计时、对接释放、退出重进，以及多邮箱包裹过滤。只在用户要求时启动客户端，不自主运行服务端测试。
