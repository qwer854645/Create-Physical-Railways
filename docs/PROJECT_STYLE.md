# 项目语言与 UI 规范

版本：1.0.0 · 状态：默认生效 · 参考：Create 6.0.10-280

本项目采用与机械动力一致的部件命名、操作提示和工业像素界面。要求是用词准确、说明简洁、信息分层、材质统一。不是给所有内容添加黄铜边框，也不是把文案写得更复杂。

## 读取方式与适用范围

- **唯一规范数据源**：[project-style.json](project-style.json)
- **结构约束**：[project-style.schema.json](project-style.schema.json)，使用 JSON Schema Draft 2020-12
- **自动加载入口**：根目录 `AGENTS.md` 与 `.cursor/rules/project-style.mdc`

新增或修改物品名称、工具提示、交互消息、界面、HUD、配置说明和无障碍文本前，先读取 JSON 和本说明。默认覆盖整个项目及以后新增的功能；不要求开发日志、代码标识符、技术文档或日常讨论模仿游戏内短提示。

程序读取顺序：核对 `id`、`version`、`status`，按 `scope` 判断范围，再读取 `terminology`、`copy` 与 `ui`。规则通过稳定的 `id` 标识；`level: must` 是必须遵守，`should` 是可说明理由后调整的建议。`automated: true` 仅表示现有检查覆盖其中一部分，不等于整条规则已被机器证明。

颜色使用 `#AARRGGBB`。以 `@create.` 开头的值表示从 Create API 读取，不是十六进制颜色。`references` 中的资源路径指依赖包内资源，不是本仓库文件；其余源码路径相对仓库根目录。

用户明确要求优先于默认规范。临时例外按该次要求执行；长期调整同步修改 JSON 与本说明，结构变化还要修改 Schema。两份描述有分歧时以 JSON 为准并修正文档。规范结构不兼容变化提升主版本，新增兼容字段提升次版本，措辞修正提升修订版本；调整时保留既有规则 ID。

## 语言风格

### 名称与术语

名称描述部件本身，不带“原型”“测试版”等开发阶段字样。同一功能保持一个名称，完整名称用于物品和首次介绍，短称用于上下文明确的按钮、状态与说明。

- 物理转向架 / Physical Bogey；短称“转向架”
- 转向架安装座 / Bogey Mount；短称“安装座”
- 物理列车驾驶台 / Physical Train Controls；短称“驾驶台”
- 车钩 / Train Coupler；连接与断开使用“连挂 / couple”“解挂 / uncouple”
- 时刻表 / Schedule；重新放回铁路使用“重新上轨 / rerail”
- 操作使用“右击 / R-Click”“潜行右击 / Sneak-R-Click”；持续操作明确写“按住右键”

完整词汇及避免用语见 JSON 的 `terminology`。英文沿用 Create 的 **Bogey** 拼法。部件名与按钮用标题式大小写，状态和解释用句式大小写。

### 先准确，再简短

名称用名词，按钮用短动作，状态先说正在发生什么。拒绝提示说明原因，能给出恢复操作时就给出，不把技术异常直接显示给玩家。

- 按钮：`取回时刻表` / `Retrieve Schedule`
- 状态：`时刻表已暂停` / `Schedule paused`
- 操作限制：`停车后才能重新上轨` / `Stop the carriage before rerailing`
- 条件说明：`使用扳手右击时：切换制动`
- 数值标签：`目标：%s 格/秒` / `Target: %s blocks/s`

短标签、按钮和提示末尾不加句号。中文标签用全角冒号，英文用冒号加空格。常驻文案只保留判断和操作需要的信息；操作顺序、限制与补充解释放到分行悬停帮助中。避免重复提示和内部实现细节。

必须区分目标速度与实际速度、查看与接管、退出与制动、参数编辑与驾驶操作。不要承诺必然达到目标车速，不沿用旧热键或已经移除的行为。上面的示例是措辞模板，不是要求其他部件也实现相同功能。

可重绑按键使用动作名称或实际绑定名称，不把默认 W/A/S/D 写成永远有效的控制方式。速度使用“格/秒 / blocks/s”，输入转速使用 RPM。P1～P8 表示牵引档，B1～B4 表示制动档；当前牵引档设定是绝对目标速度，不写成出力百分比。

### 翻译与错误处理

玩家文案使用翻译键，并同时维护 `zh_cn.json`、`en_us.json`。两种语言键集合及格式参数类型、数量和顺序一致，允许按语言习惯重写句子，不逐字硬译。

使用 `itemGroup`、`item`、`block`、`tooltip`、`gui`、`message`、`config` 对应的 `guidedrailways` 键前缀。文件使用 UTF-8，新增文件采用 LF。JSON 字符串的 `\n` 应解析成实际换行，经 `UserText` 按行展开，不能让玩家看到字面量反斜杠 n。

交互异常经 `UserText.error` 转换为翻译组件。未知技术异常写日志，玩家收到简短通用提示。Sable 默认物理体命名接口只接收字符串，因此使用创建时服务端语言，这是现有接口限制。

## UI 风格

### 原生材质与集中复用

优先运行时引用 Create 原生 GUI 纹理和图标。面板使用 `AllGuiTextures.SCHEDULE_EDITOR`，按钮使用 `BUTTON`、`BUTTON_HOVER`、`BUTTON_DOWN`、`BUTTON_GREEN`、`BUTTON_DISABLED`。确认使用 `AllIcons.I_CONFIRM`，时刻表使用 `AllIcons.I_SCROLL`；新增图标按功能选择，不把时刻表图标用于无关操作。

只拼接纹理中的干净区域，不把源图已有物品槽、字段或按钮带入新面板。保持原生像素尺寸，以平铺延展边框和中段，不拉糊边框，不任意缩放字体或图标。升级 Create 后重新核对纹理坐标和控件 API。

新增界面、HUD 和控件复用：

- `CreateGuiTheme.java`：面板、凹槽、颜色、按钮材质和文本适配
- `CreateActionButton.java`：统一按钮状态、图标与完整文本提示
- `UserText.java`：翻译消息、异常转换和分行工具提示

新增视觉材料集中到主题适配层，不在每个 Screen 复制配色和绘制逻辑。不要混入 Minecraft 默认按钮皮肤、旧黄铜外框、青绿高亮、发光渐变或现代网页式控件。

### 颜色、尺寸与状态

视觉骨架是灰色压边与纹理侧边，深灰凹槽承载信息和输入。正文浅灰，次要信息稍暗，金色只用于当前档位或少量重要信息。精确颜色见 JSON 的 `ui.palette`；标题色跟随 Create 的 `AllGuiTextures.FONT_COLOR`。

按钮高 18 个 GUI 像素，原生图标 16 个 GUI 像素。300 × 240 是当前驾驶台参考尺寸，不是所有窗口的硬性大小；按内容布局，保持像素比例。0.1 是当前速度编辑器步长，不是所有数值控件的通用精度。

按钮区分常态、蓝灰悬停、按下、绿色选中与禁用。选中表示当前选择，不等于可点击；无权限或只读状态必须保持清楚。数字输入去掉默认黑框，放入主题凹槽；滑杆、操纵杆握柄和刻度使用同套材质。

### 信息层级与交互

当前驾驶台按速度与动力、方向、时刻表、操作区组织；档位编辑单独成页。其他界面按自身任务分区，保持一致的边距、对齐和操作顺序。不因设置界面改版重新加入背包、快捷栏或物品槽，除非用户明确要求。

同时考虑中文与英文宽度。长文本省略时提供完整悬停内容，不覆盖相邻控件，不截断重要数值或单位。兼顾不同 GUI 缩放；绘制位置、焦点和命中区域一致。

外观修改必须保留点击、键盘、焦点、拖动、只读和无障碍提示的语义。编辑档位参数不应直接操作列车；查看自动驾驶不应隐式接管；客户端显示状态不能代替服务端权限验证。

## 修改与验证流程

1. 读取规范，核对实际行为、已有术语和可复用控件
2. 同步更新中英文文案，使用统一主题实现界面
3. 修改规范数据时，使用支持 Draft 2020-12 的校验器按本地 Schema 校验；另外核对规则 ID 唯一、引用文件存在、参考版本与依赖一致
4. 文案修改运行 `gradlew.bat checkLanguage --offline`；代码/UI 修改运行相关检查和 `gradlew.bat build --offline`
5. 列出手动测试场景：两种语言、按钮全部状态、长文本、GUI 缩放、键盘焦点、拖动、只读与权限
6. 依用户要求打开客户端、观察日志、听取测试结果，再提出下一步计划；不自行开启服务器进行游戏测试

现有语言检查覆盖键集合、占位符、部分标点与换行、翻译引用及硬编码残留，不会证明全部措辞质量，也不会验证视觉效果或所有新控件的主题使用。Schema 约束规范数据结构，不会自动修复 UI。未进行客户端验证时应明确说明，不把构建通过写成视觉验收通过。
