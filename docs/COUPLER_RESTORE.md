# 车钩读档恢复（0.1.62）

用户反馈读档后外观保持连挂，实际车钩却没有牵引效果。对应日志中保存的连挂记录仍存在（连接工具可以解开该记录），但读档后没有 CouplerJoint 创建记录，也没有 CouplerState 活跃关节日志。这说明该次会话没有成功重建可供列车分组与牵引使用的物理连接

旧实现依赖方块实体 tick 将车钩注册到运行时端点表。物理体区块加载后，方块实体可能仍以 packed NBT 存在，依赖实体自己 tick 无法覆盖这段恢复流程；缺少任一端时原逻辑安静返回，未解释等待状态

## 本版处理

- 本模组车钩在 onLoad 注册；Railway 的可染色车钩和复制车头板实体也在加载时注册，原来的 tick 注册保留，用于物理体移动和稍后就绪的重试
- 每次主世界逻辑 tick 先检查保存配对；存在未注册／未加载端点时，最多每 20 tick 扫描一次已经加载的物理体区块，仅展开其中属于车钩的方块实体并注册
- 不请求加载远处车体或区块；保存配对在单端卸载时保留，两端恢复后继续由原关节恢复流程建立标准长度的自由转向连接
- 物理步继续核对关节有效性和所属物理体，失效或移动后重建。新增 CouplerRestore 等待原因日志，区分端点未注册、物理体未就绪和闭锁动画未完成；只在等待原因变化时输出
- 本模组原车钩的磁盘 write 现在也保存 VisualPeer 和 VisualPeerPos，与网络同步及 Railway 嵌套数据一致。以前仅 update-tag/save 辅助路径保存这些字段，重读后确认对端会再次启动闭锁动画。当前只读取 CouplerVersion=6 的几何格式，不再迁移早期插座长度或动画机构版本
- 注册时发现没有对应保存配对的残留闭锁显示会清除，不将外观标志反向当作创建新连接的依据

连接距离、弹簧、缓冲行程、类型限制及连挂工具操作保持原规则。没有根据当前位置自动连接陌生车钩

## 验证与客户端场景

`gradlew.bat checkCouplerPersistence --offline` 使用实际 Minecraft NBT 类执行磁盘路径往返，不创建世界或服务器。检查稳定端点 UUID、对端信息、物理锚点与标准长度、未完成动画时间线，以及历史几何版本拒绝读取

1. 本模组车钩连接两辆车，保存退出，再进入；不用重新点击车钩，单端起步应带动另一辆，日志出现 CouplerJoint 和 CouplerState
2. Railway 詹氏、链销和螺旋车钩分别检查同样流程；在动画中退出时，重进后应继续完成闭锁
3. 连挂编组退出重进，检查驾驶台对整列的识别和动力分配；回归时刻表、货物完整性检查
4. 单端卸载再恢复时，保存配对不丢失；等待日志不逐帧刷屏，两端加载后重建关节
5. 解挂后保存重进，外观与实际连接均应断开；再连接、拆除或粘合移动一端，检查没有重复端点或残留关节

自动检查不能证明区块生命周期和真实物理约束已在游戏内通过，须以上述客户端观测为准


## 0.2.1 拆除与动态碰撞

在 BlockState.onRemove 入口通知解挂，早于 IBE/Copycat 的方块实体失效流程；Sable beforeMove 标记的结构搬运仍保留连接，正常卸载仍等待恢复。解挂同时清空对端 UUID、位置和碰撞缓存，序列化复用的标签也移除对端字段，避免动画误认旧连接。

Railway 玩家碰撞不再使用固定模型形状：NativeCouplerAnimation 统一钩头摆动、钩舌开闭、插销升降、链环和螺杆变换，渲染器与玩家碰撞共用。模型元素只解析一次，每个端点的动态碰撞每 tick 缓存一次；每个旋转元素转换为局部包围盒后取并集，因此轮廓是逐元素近似，非三角网格精确碰撞。固定安装座及缓冲板保留原碰撞，车体之间的物理接触仍走固定碰撞与车钩约束，避免移动链环参与刚体求解而重新卡住。

Railway 方块通过适配层 hasDynamicShape 绕过原版静态碰撞缓存，不修改 Railway jar。动态模型只用于物理结构上的车钩，世界中的普通装饰保持静态模型碰撞。

验证：完整离线构建、2,800 个共享变换与原渲染逐点计算对照、车钩断开数据序列化检查通过。客户端启动及已加载车辆的关节恢复未出现新 Mixin 或形状回退错误。拆除传播和玩家接触效果仍待用户实机确认。

追加回归：本模组车钩与 Railway 各类独立/木质/伪装安装车钩分别连挂后拆掉一端，立即检查另一端、随后保存重进；弯道及错位连挂时玩家接触钩头/链环，检查碰撞随模型移动，安装座不动；回归缓冲板接触和原有车体连挂稳定性。
