# 稳定性基线与验收

暂停增加功能，按完整生命周期稳定现有行为。一次只改一条链路，先把原有缺陷、权威数据、修改和验收结果对应起来，再扩大范围。构建或局部回归通过不等于游戏内验收通过。

## 第一阶段：车钩身份与搬移

本阶段针对同一个问题：连接身份已保存，搬移凭据却会在临时表过期、世界卸载或重启后丢失，导致正常搬移的端点被当成副本。连续搬移及部分提交后再次搬移也必须保留正确来源。

### 数据归属

- `CouplerSavedData`：当前维度真实连接的唯一权威，保存配对及已登记端点的位置。卸载不删除配对，明确解挂或合法拆除才删除
- `CouplerEndpoint`：真实方块实体附带的局部几何、动画和未完成搬移请求。请求随本模组及 Railway 的实际方块实体 NBT 保存，不独立创建连接
- `CouplerHandoff`：来源、唯一目标位置及原世界插座几何。提交必须核对端点身份、维度、位置和保存归属；它只请求已有连接的位置变更
- `CouplerTransfers`：无状态的 Sable 回调适配器，不保存静态交接表或超时表
- `CouplerConnections` 的运行注册表与关节：已加载对象的临时引用，可以释放、重建，不能据此删除存档里的连接

### 转换约定

1. 搬移前保存请求，再释放源端的运行关节。Sable 在 `beforeMove` 后保存 NBT、在加载目标 NBT 后调用 `afterMove`；离线契约检查约束这一顺序
2. 目标物理体／质量尚未就绪时等待，不改写已保存归属。请求不按游戏刻过期，保存重读后继续等待
3. 等待期间再次搬移，延用原来源及世界几何，更新最终目标。不能把旧局部坐标当作新物理体上的坐标
4. 目标就绪后提交保存归属，立即将请求来源更新到已提交位置，再恢复局部插座。后续重试或再次搬移使用已提交位置
5. 异地副本不能消费原请求、接管原连接或授权拆除；失败后留在原地的源端不会凭旧请求授权另一位置
6. 正常卸载只释放运行对象。删除合法的待恢复目标也必须删除配对，不能因为它尚未完成恢复而遗留连接
7. 跨维度仍按原规则先解挂，不支持跨维度物理关节。旧存档缺少归属位置时首次登记，不能追溯识别登记前的历史副本

### 固定验收场景

以下代码路径已有离线回归；真实回调执行、物理关节、动画和驾驶效果仍待游戏内验收。本阶段不自动启动客户端或服务器。

1. **普通连接与读档**：本模组车钩、Railway 车钩各连挂两辆车，保存重进；外观保持连接，实际起步能带动另一辆，出现关节创建日志
2. **副本隔离**：复制已连挂端点，原件卸载后先加载副本，再拆副本；原件读回后仍连接原对端，副本不得拉动或解开原连接
3. **搬移及连续搬移**：粘合搬移连接的一端或两端，继续粘合到另一车体，再反向搬回；不要求重新连挂，不出现原地残留关节
4. **等待与重读**：在恢复尚未完成时保存退出，再进入；检查等待结束后身份与连接恢复。离线回归显式传入未就绪状态并多次序列化，不把它当成真实区块加载测试
5. **待恢复时拆除**：合法目标尚待恢复时拆掉车钩；对端也应断开。普通卸载不应造成同样结果

验收记录应写明车型、连挂类型、操作顺序、是否重进及对应日志，记录“未测／通过／失败”，不使用构建任务数量代替结论。

## 第二阶段：驾驶台接管与时刻表恢复

### 数据归属与边界

- `ScheduleController` 是时刻表物品、条目、等待条件进度、保存编组和自动运行意图的权威；运行路线是可重建缓存，不保存路线对象
- `TrainConsists`、车钩关节和货物编组是已加载状态的视图。缺少已保存的转向架或车钩尚未恢复，不能单独证明玩家改变了编组
- `ScheduleReloadGate` 只负责就绪判断，不改写时刻表；读档后的匹配编组连续稳定 10 次才恢复规划
- 玩家操作会话不随存档恢复。退出观察不停止自动运行；退出手动操作仍沿用既有保速行为；暂停、紧急制动和明确接管分别走现有转换
- 控制台主从选举仍使用既有放置顺序。本轮没有更改选举算法，也没有证明任意加载顺序下的全部选举行为

### 本轮修改

1. 读档恢复同时核对车钩恢复状态和保存的转向架集合；不再因等待超过 200 刻就把缺少车辆判成编组改变
2. 运行中的已加载编组先检查连接完整性，再核对成员。暂时缺少保存成员时保持等待，不用局部集合覆盖原记录
3. 已完整加载但多出成员时保留原编组变更判断；读档阶段仍保留 200 刻确认窗口。明确连挂／解挂在待恢复阶段取消恢复，在已运行阶段仍沿用原来的编组重规划
4. 右击待恢复的驾驶台进入观察，不隐式取消时刻表。GUI 在待恢复时提供暂停，明确接管仍由按钮执行；暂停和接管都会清除待恢复状态
5. 不修改驱动力、车速、制动参数或物理关节

等待有明确限制：如果保存成员永久丢失，且没有收到合法拆除／编组变更事件，系统无法仅凭缺席区分丢失与未加载，会持续等待。玩家可以暂停、明确接管或重新启动时刻表，不再用超时猜测并丢弃恢复意图。本轮不改变整组完全无法关联到轨道转向架时的既有停运规则。

### 验证与固定场景（2026-10-23）

离线回归覆盖实际恢复判断器的延迟成员、连接未就绪、稳定期被打断、额外成员，以及运行边界传入就绪信息和观察／暂停入口。字节码契约只能约束调用和状态写入边界，不能代替实际玩家操作或区块加载验收。

完整离线构建与语言检查通过；恢复判断器、生命周期回放和调用边界检查通过。以下均待游戏内验收，本轮不启动客户端或服务器：

1. 两辆连挂列车自动运行中保存重进，包含到站等待条件；完整恢复后继续原条目和条件进度，不误报编组改变
2. 尾车暂时未加载或车钩等待恢复时，主车等待；车辆恢复后继续。等待中再次保存退出，重进仍保留恢复意图
3. 待恢复时右击驾驶台只观察；退出观察不取消恢复；GUI 暂停后不自动重启；明确接管后可以手动操作
4. 待恢复时明确解挂／连挂，原恢复停止；手动重新启动后以当前编组运行
5. 多驾驶台列车保存重进，检查主驾驶台选举、从驾驶台权限及紧急制动仍符合原规则


## 第三阶段：货物观测与等待条件

本阶段仍不改真实容器的存取方式，也不聚合成原版列车库存。`CargoStorage` 只读取当前完整编组内的真实容器；快照可失效，`CargoTransfers` 的成功传输时钟不能被读取缓存代替。`ScheduleController` 保存条件进度，货运观测时间戳属于可重建的临时状态。

### 中断期间误算空闲（2026-10-23）

发现：当连接不完整、路线不可用或邮件交换尚未就绪时，上层会跳过 `tickConditions`，原 `CargoWaitStarted` 却仍保留。重新开始检查时，间隔可能直接满足空闲时长，尽管这段时间没有完整货运观测。

修改：货运空闲同时记录最后一次有效观测刻。相邻有效观测最多间隔 1 刻，同刻重复读取允许；更长中断或时间倒退都会重新开始空闲计时。检测到容器／监测不完整以及读档时，统一清理观测时间戳和数量检查节流时间，不清除条件分支的已完成进度。成功传输仍通过原时钟重置空闲，不靠最终库存是否变化来猜测传输。

离线回归使用实际条件上下文和生产计时方法，覆盖连续空闲、中断后恢复、同刻重复读取、成功传输、读档清理及时间回退；调用边界检查保证真实条件执行和读档路径使用这些方法。

待游戏验收：

1. 正常装卸完成后，完整空闲指定时长才发车；模拟查询不重置，实际传输重置，即使最终库存数量不变
2. 到站等待货运空闲期间中断编组连接或加载，恢复后重新等待完整空闲时长，不立即发车
3. 同一条件在暂停后恢复、明确接管后重新启动、保存重进后重新等待；已完成的前置条件保持进度
4. 物品数量、流体数量条件及并行分支保持原行为，本轮没有修改阈值、比较符或真实物品输送

完整离线构建、货物回归及生命周期调用边界检查通过。未启动客户端或服务器，以上游戏行为仍未测。

## 第四阶段：转向架与安装座归属版本

本阶段处理“同一个坐标被先后两次占用”的情况：平台拆除后在同一格重新放置，或搬移往返回到原位置。只按维度与坐标认主时，这两次占用在存档里完全一样，等待中的旧搬移请求仍能通过位置核对。

### 数据归属

- `MountOwnership`：纯 Java 规则，保存平台位置和搬移版本。位置可由后来的平台复用，版本只增不减，因此 A→B→A 是版本 2，不是最初那次占用
- `BogieMountBinding`：把 `MountOwnership` 写入下部物理体的用户数据（`GuidedMount`），沿用原有 `Dimension`／`Position`，新增 `Revision`；旧存档缺少该字段时按版本 0 读取
- `MountHandoff`：授权的来源与唯一目标，新增 `SourceRevision` 记录授权时实际观察到的版本；旧存档或授权时下部物理体尚未加载时记为未知
- `MountEntity.handoff`：随平台方块实体 NBT 保存的待完成交接，不独立成为另一个权威
- `VehiclePhysics` 的 `INPUTS`／`ACTIVE`：已加载对象的临时引用，可重建，不参与归属判定

### 转换约定

1. 搬移提交是对归属的比较并交换：来源位置必须吻合，且当授权时观察过版本，版本也必须吻合；否则拒绝并记录 `[MountClaim]`，不覆盖更新的归属
2. 已记录目标位置时重复回调是幂等的，不再递增版本。这样 Sable 重复投递同一搬移不会制造新版本
3. 授权时下部物理体未加载、版本不可观测，仍按原来的位置规则处理，避免把正常搬移误判成副本
4. 被拒绝的交接与原来一致地解除该平台的上轨绑定，不把仍属他人的下部物理体留在自己名下
5. 版本到上限时拒绝写入，不在任何修改之前溢出
6. 本阶段不修改驱动、车速、制动、轨道导向或碰撞参数

### 固定验收场景

以下路径已有离线回归；真实 Sable 回调时序、物理关节和驾驶效果仍待游戏内验收，本轮不启动客户端或服务器。

1. **正常搬移往返**：一辆车安装转向架后在物理结构间搬移 A→B，再搬回 A；两次都正常行驶，日志中没有 `[MountClaim]` 拒绝记录
2. **同一格重新放置**：拆除平台后在同一格重新放置并重新安装，正常认主；旧平台的存档副本不能接管
3. **等待中再次搬移**：交接尚未完成时继续搬移到第三处；沿用原来源与最终目标，完成后不停在中间位置
4. **保存重进**：交接等待中保存退出，重进后继续完成；`Revision` 与 `SourceRevision` 不因重进而重置
5. **副本隔离**：复制平台方块 NBT 后先加载副本；副本不得认主、不得消费原交接

## 第五阶段：重新上轨、轴承刚性与渲染开销

本阶段处理三个只在真实游戏里才暴露的问题：重新上轨永远被拒、平台在行驶中自己左右倒、某款转向架第一次进入视野时掉帧。三者都先有实测证据再改，改动范围限于对应链路。

### 重新上轨的坐标系

- **现象**：任何重新上轨都被拒绝，聊天栏提示“目标位置所在区域尚未加载”，每次点击还伴随明显卡顿
- **证据**：`[RerailSpace] target area chunk not loaded pos={x=-8645,y=69,z=28973253}`，而同一批目标车体的 `posePos` 是玩家身边的 `50,-58,7`；单次点击被拒 56 次，日志里 `[MountClaim]` 为 0
- **根因**：`RerailSpace.shapes()` 用物理 pose 变换 plot 空间的方块坐标，却没有补 `logicalPose().rotationPoint()`。`Pose3d.transformPosition` 的语义是“减去旋转点后旋转、再加位置”，旋转点为 0 时等于把 2000 万量级的绝对坐标当矢量旋转，整个车体被判到 2900 万格外；包围盒被撑大后，地形校验扫到的是永不加载的绘图区
- **修法**：变换前把 `logicalPose().rotationPoint()` 写入 pose；两种“未加载”拆成 `space_unloaded_area` / `space_unloaded_body` 并记录坐标或车体 ID
- **回归**：`Frames.toWorld` 抽成纯函数，`FramesCheck` 用 2000 万量级原点覆盖“补旋转点正确 / 漏掉后偏移超过 1e7”；`RerailSpaceCheck` 增加字节码断言，要求 `shapes()` 确实读取 `rotationPoint`

### 轴承刚性

- **现象**：转向架顶上的平台在行驶中自己左右倒（滚转），静止时不出现
- **证据**：车身局部 X 轴沿行驶方向（导向约束只放开 `LINEAR_X`），故 `ANGULAR_X` 是滚转、`ANGULAR_Z` 是俯仰、`ANGULAR_Y` 是偏航；旧代码对多副转向架只锁俯仰，并给滚转留了 ±0.35 rad 的活动量和一个纯阻尼 motor
- **修法**：滚转与俯仰在任何转向架数量下都锁死；偏航保留（一个车身下挂多副转向架时，各转向架在弯道朝向不同，锁死偏航会让同一车身收到两个互相冲突的朝向约束），只做回正，预算按转向架数量分摊（13 行的 `18/60/360` 取代原先的 `12/18/120`）
- **回归**：`BearingLock` 纯策略 + `FramesCheck` 断言 `locked(n)` 恒为 {滚转, 俯仰}、永不含偏航、预算按数量分摊；`TrainRuntimeCheck` 断言 `connectPivot` 经由该策略而不是内联轴表

### 渲染开销

- **现象**：主世界靠近火车时帧率不稳，偶发掉到 30；下界（无物理体）稳定
- **证据**：`[BogieRender]`（`detailedLogging` 开关）稳态 `meanMs=0.087~0.126`、`maxMs<2.3`，即单次绘制 0.1 ms、一帧约 3 次；但新款式**首次绘制**是 `13.9 / 25.2 / 26.9 / 30.8 / 38.3 / 53.0 ms`，且全部集中在进世界后的头 30 秒，之后不再出现
- **修法**：`BogiePrewarm` 在方块实体加载时登记款式，每客户端刻烘焙一款并提交缓冲区，把首帧成本挪到区块加载期；`NativeBogeyModels` 按款式缓存 style/size，不再每帧解析两个标识符
- **本机环境调优**（不进 Git）：`sable-client.toml` 的 `debug_draw_loaded_chunks` 与 `sub_level_dynamic_shading` 关闭后收益明显；`build.gradle` 不再强制 `workerThreads=0`（该值让网格构建落在渲染线程），可用 `-PflywheelWorkers=0` 退回。发布说明应提示玩家这三项与帧率相关
