# 货运访问边界与统一验收

适用：0.2.22 · Minecraft 1.21.1 / NeoForge / Create 6.0.10

## 规则

物理车体、车钩编组和容器输送网络是不同范围。粘合方块或连挂车辆只建立物理关系，不使箱子、水箱互通。箱子与连接器之间必须通过原有漏斗、传送带、管道或模组自身的显式连接输送。同一车体上的独立容器也不自动互通。

CargoStorage 可按整列汇总时刻表条件与观察器货物过滤；原生 Carriage.storage 按车厢提供只读视图。两者都不是可写的整列仓库，不可用统计位置列表作为装卸目的地。原生可移式接口与跨维度整列迁移不在本次范围。

## 本次发现与修改

1. 原包裹交换在验证一次铁路对接后，通过 packageInventories 遍历整列任意可写箱子。这会绕过真实连接器和容器输送路径，已删除该入口。
2. 包裹交换改为通过已绑定车站、当前控制器持有自动锁定请求、互相配对并双端锁定的铁路连接器。使用站台端原生双槽接口：槽 0 仅向车载端本地缓冲插入，槽 1 仅从站台端本地缓冲提取。站台关联邮箱是明确的邮件端点；不会因此访问整列箱子。车载容器需要把待卸邮件输送到连接器，并将装入车载缓冲的邮件运走。
3. 原 Automated Logistics 货物链接快照会从玩家选择的容器扩展到同一车钩编组全部同类型容器。已移除该 Mixin 与扩展逻辑，恢复上游显式选择范围；保留连接器实际交换活动记录和地址检查。
4. 包裹缓冲视图每次操作重新检查控制器、车站绑定、当前方块实体、加载状态、编组成员、车钩恢复完整性、请求所有者及有效期、互相配对和双端锁定。拆卸、替换、解挂、改接或释放请求后，旧视图不能继续写入。两端有修改时均标记保存，并更新车载装卸活动。
5. 铁路连接器公开物品能力在每次调用时解析当前配对，端点替换或卸载后返回不可用；非互相配对或未锁定的对端不会作为双端库存暴露。流体能力也增加本端实体存活检查，上游储罐仍负责当前实际对端校验。
6. 包裹外发规则统一排除本站所有关联邮箱的地址，并在实际装入及等待检查中应用取件过滤器，避免将本站另一邮箱的邮件误当作外发，或因不符合取件条件的邮件一直等待。站台缓冲里尚未进入邮箱的本站邮件也会阻止包裹任务提前结束。

## 三类连接器的范围

- Hose Connectors：本项目仅读取并监测软管本地缓冲，未增加跨车厢抽取；实际输送、配对和流向由上游负责，本轮没有重写其能力或网络
- Simulated / 铁路对接连接器：普通物品和流体沿原生配对接口；铁路包裹交换仅使用上述已验证的一对缓冲和车站关联邮箱
- Automated Logistics：容器选择恢复上游范围，原生对接缓冲交接与本项目的地址限制保留，不再因为连挂而隐式增加容器

没有移动或清空现有存档库存。旧世界中原先放在任意车载箱子、且没有接入输送设施的邮件，将不再直接装卸；需要玩家补上实际输送路径。派送任务仍可按整列货物选站，未接入的匹配邮件可能使任务继续等待，这不代表邮件已通过连接器卸下。

## 统一人工验收

暂不自动启动客户端或服务器，最后集中进行以下检查：

1. 同一物理车体上放 A/B 两个独立箱子，仅 A 接入输送设施。装卸只能影响 A；B 内容保持，驾驶台货物条件和 /physicalrailways cargo 仍可统计 A+B
2. 两个连挂车厢各放箱子，仅头车连接器实际对接。尾车没有接入的箱子不被直接抽取或装入；解挂前后均不能产生隐式输送网络
3. 正常邮件卸载：车载箱子 → 原有输送设施 → 铁路连接器 → 本站邮箱；匹配地址进入邮箱，非本站地址保留，观察真实缓冲和总数
4. 正常取件：本站外发邮箱 → 铁路连接器车载缓冲 → 原有输送设施 → 指定箱子；缓冲满时等待，清空后继续，未接入箱子不能凭空收到邮件
5. 同站多邮箱、通配符地址、取件过滤器、满仓、重复停站与两车同时请求，确认无丢失、复制、卸错站或越过被占用的对接端点；邮箱满时站台缓冲内的本站邮件不能被当作已投递
6. 装卸时暂停、取回时刻表、移走或拆掉任一连接器、原位换新连接器、改绑车站或解挂。旧引用不能继续转移；修复并重新对接后恢复
7. 对接或满仓等待期间退出重进、卸载并返回，两端缓冲和箱子内容保持，原控制器重新建立有效请求后才继续装卸
8. Automated Logistics 只选择 A 箱或 A 储罐，另在同车体和尾车放未选容器，核对其快照/货物条件只覆盖上游明确选择；普通地面网络回归
9. Hose 与 Simulated 普通物品/流体双向输送、堵塞、断开与重连，确认上游路径正常，本列统计不包含站台库存
10. 回归整列数量条件、装卸空闲和观察器过滤；同车体多转向架不重复统计，未知或未加载车厢不被当作空载

日志关注 [RailDock]、[RailDockPower]、[PackageMail]、Cargo compatibility API unavailable 和库存/保存异常。离线接口检查不能替代真实 Mixin 应用和上游管线输送验收。
