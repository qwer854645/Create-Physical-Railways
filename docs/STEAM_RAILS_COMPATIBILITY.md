# Steam 'n' Rails NeoForge 兼容

基线：Minecraft 1.21.1 / NeoForge 21.1.233 / Create 6.0.10-280 / Steam 'n' Rails 0.3.0-beta.2+neoforge-mc1.21.1

发布包来源：https://www.curseforge.com/minecraft/mc-mods/steam-n-rails-neoforge/files/8522154

发布包 SHA-256：`64b74ddad661deae1cfe7e8334cfa3d39bb8ef7b761f83595ba0476c4a9bb1d5`

可选模组 ID 为 `railways`。发布 jar 放在忽略的 `libs/`，只作编译接口和开发运行依赖，不复制进本模组发布包。发布包要求 NeoForge >=21.1.233，因此同步开发环境。保持 Create 6.0.10-280，实际与 Beta 的组合需客户端验收。

## 已实现：轨道与道岔

标准轨判断使用 TrackMaterial.trackType，而不是材质名称；支持所有 STANDARD 材质和通用轨，拒绝未知类型。放置、恢复导向、节点过渡和自动规划统一检查。

道岔适配使用发布 jar 的 ISwitchDisabledEdge。几何连通查询在 try/finally 中暂时跳过道岔状态，规划另行检查 enabled/automatic；实际通过必须等待分支开放。自动道岔使用原生自动选择请求，不能切换已锁定的自动道岔。驾驶默认优先开放出口，显式时刻表路线与编组历史优先于角度选择。

制动距离内提前请求，未开放时整列制动，不瞬移车体。编组对同一节点的穿越保持预约，允许倒退沿原路，保留到所有轮轴及节点附近的重复穿越记录清除，再等待心跳超时释放。其他物理列车不能夺走有效预约；原版列车仍通过原有信号占用协调，不伪造其 Train 身份。外部玩家强制改岔时，已跨岔编组仍沿提交的路径通过，后续进岔车辆需等待。

待测：两种道岔的正反向、左右选择、锁定、红石改岔、自动时刻表切岔、长编组通过中尝试改岔、两列车竞争、暂停/拆除后释放与原版混跑。

## 已实现：信号与止冲挡

轨旁 TrackBuffer 从轨道图边点读取。以实际车体前端投影加余量计算制动距离，手动、裸应力驱动与自动模式共享前方障碍制动。Dijkstra 逐段检查初始部分边与目标部分边，禁止规划穿过止冲挡，允许到达挡车器之前的站点和远离身后挡车器。

车站是否启用读取 Beta 的 ILimitedGlobalStation；规划与运行中的目标有效性均检查。物理列车的区段占用仍经过现有 SignalEdgeGroup 桥接，机械臂信号机读取原生 SignalBlockEntity，不添加平行显示状态。原生列车的完整列车计数限制不是物理列车数量注册，不能据此宣称该计数已经包含物理编组。

待测：各轨距挡车器、弯轨上的挡车器、长车前端余量、停车后反向离开、目标位于挡车器前/后、信号红黄绿与机械臂显示、原版/物理列车混跑，以及目标站禁用后恢复。

## 已实现：窄轨与宽轨

新增窄轨/宽轨物理转向架物品和条件配方，安装座记录稳定 RailGauge 字符串，装配移动保留类型，旧存档默认 STANDARD。按款式返还物品，不通过最近铁轨临时猜测轮距。创造物品栏只在安装 railways 时展示新增款式。

沿用本模组现有小转向架的外观，以标准款为基础将横向宽度分别调整为 0.5/1.5；细碰撞同步变换并重新分割为实际占用方块，保持单一下部物理体，不增加轮子物理体。碰撞缓存、渲染包围盒、两转向架防嵌入包络同时按款式处理。

放置/重新上轨、恢复导向、跨节点与预判制动使用实际款式。自动路线对整列所有款式取兼容交集；同车体多个安装座上轨同样验证全部款式。通用轨可承载三种普通轮轨款式，不能当作单轨梁。

待测：窄/宽直弯坡、瞄准弯轨、错误轨距拒绝、多转向架重新上轨、粘合移动、退出重进、创造/生存拆卸返还、模型与碰撞边界、不同款式互撞不嵌入，以及跨轨距寻路拒绝。

## 已实现：单轨转向架

新增单轨物理转向架物品/条件配方，仅接受 MONORAIL 轨道类型。使用安装的 Steam 'n' Rails MONOBOGEY 原生动画模型与纹理，不复制原生资产。轮距类型、导向/上轨点、模型、细碰撞、相撞包络、拆卸返还与存档保持一致，下部仍只有一个物理体。

单轨模型基准对齐一格高梁，导向参考高度 1.0，安装平台顶面仍为轨道基准+2 格。安装座和拟合器使用对应支承高度，不通过把标准轮子横向缩小来模拟单轨。碰撞使用模型构架的测量包络与水平轮的扫掠圆盘，内侧为梁翼缘留有微小间隙。首版为梁上跨坐款，未增加倒挂式安装入口。

待测：直梁/弯梁/坡梁、梁上放置和车体下安装、反向行驶、同体多单轨转向架、顶部接应力、平台整格高度、侧轮动画方向、梁侧碰撞、车钩编组、重新上轨和存档恢复。单轨与普通轨距混装的编组没有共同可行线路时应拒绝寻路。

## 已实现：轨旁连挂设备

Steam 'n' Rails 原生轨旁连挂器两处轨道标记分别识别本模组轮轴所在的实际轨道边与车体，不靠附近方块或平行线路的世界距离猜测。需要两节车各自的转向架停在标记附近，并安装本模组物理车钩，调整原生设备的标记间距匹配车辆。红石上升沿调用现有车钩连挂/解挂，保持固定拉杆长度和小范围伸缩，不建立第二套物理连接。

遵守原生“仅连挂/仅解挂/两者”模式；速度和角速度仍受原有安全条件限制。只连挂空闲车钩，禁止同车体、已占用端点和同编组闭环。一个标记识别物理车而另一个没有物理车时，不操作原版 Train，更不把物理车与原版 Train 强行连在一起。纯原版列车场景保留原版逻辑。

比较器沿用原生位定义：两处标记各占 1/2，解挂可用加 4，连挂可用加 8。护目镜与客户端读取服务器同步的物理操作状态。连挂后重新计算主驾驶台和整列动力，货物/成员缓存失效；保留主驾驶台时刻表指令位置，重新规划并复核当前等待条件，不复制时刻表给新车厢。拆分后尾车不会自动获得主车时刻表。

待测：原生设备间距设置、连挂/解挂/两者、持续供电只执行一次、脉冲重复操作、比较器/护目镜、移动或占用车钩拒绝、原版列车回归、主驾驶台选举、所有转向架动力重分配、自动运行中编组变化和退出重进。

## 第八步：集成检查与复现

版本为 0.1.53。集成检查修正了副手放置款式识别、不同轨距的瞄准偏移、单轨梁顶瞄准高度，以及可选连挂接口失败时错误关闭其他物流适配的问题。各款碰撞分块重新编号后，配重资源逐款指定四角，保持对称和相同总质量 80，防止配重落在错误分块上。

完成的自动验证：离线 build 成功；RailwaysCheck 1984 项断言、语言检查 2345 项断言（中英各 213 个键），其余既有检查一并通过。外部接口检查覆盖货运及连挂的 47 个签名，独立发布合同检查覆盖 13 个签名，并核对 Beta 哈希、最低 NeoForge 版本、单轨资产和发布包未夹带外部模组类。

这些检查验证源码分支、纯逻辑、几何资源和发布接口，不验证实际 Mixin 应用、渲染效果或游戏物理。可选模组缺省分支已检查，未进行卸载模组后的客户端启动验收。本轮没有打开客户端或运行游戏测试服务器。

首次离线构建之前需已有 Gradle/NeoForge 依赖缓存；准备脚本只下载固定 Beta，不提供全部构建依赖。检查脚本中的外部模组路径对应本开发环境。

## 回来后的客户端测试顺序

1. 启动检查：检查日志中 railways 适配、可选 Mixin 与模型加载是否报错；标准款在原有轨道上起停、拆装、保存重进，确认既有驾驶未回退
2. 款式检查：各款在对应直轨、弯轨、坡轨放置、行驶和重新上轨；错误轨距应拒绝；窄/宽碰撞与外观一致，单轨顶面仍为整格安装高度
3. 道岔检查：手动默认/左右选路，再运行包含自动道岔的时刻表；检查锁定、红石改岔、长编组尾车跟随、两列车等待和反向通过
4. 停车检查：各款驶向止冲挡、红灯和禁用站；确认停车位置，并能反向离开挡车器
5. 连挂检查：使用本模组物理车钩，将两车转向架对准原生设备标记；检查红石连挂/解挂、比较器、主驾驶台和时刻表状态，最后验证纯原版列车仍可使用原生设备
6. 存档与缺省依赖：保存后重进，复查款式、时刻表与连接；在备份测试存档中移除 railways 后验证标准轨功能可启动，勿用包含可选模组方块的正式存档做卸载试验

按用户流程，收集客户端日志与实际观测后再决定修复顺序；以上仍属于待测场景。
