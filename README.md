# Create: Guided Railways 0.1.5

全新实现的轨道导向物理火车原型，优先验证自由造车与驾驶手感

## 环境与边界

Minecraft 1.21.1 / NeoForge 21.1.228 / Create 6.0.10-280 / Sable 2.0.3 / Java 21
只复用已有工程的构建环境，不包含旧轮轨物理、原生补丁或参考项目的实现代码
直接读取机械动力原版轨道网络，不新增轨道、轨道碰撞体或 Create Train 实体
原版直轨与贝塞尔弯轨用于导向；原型暂不提供道岔选路、信号、跨维度或移动轨道支持

## 使用

1. 新建创造模式测试世界，从“导向铁路原型”物品栏取出“物理导向转向架”
2. 右键机械动力轨道放置，前后轮轴下方都要有连续轨道
3. 顶部平面是车体安装座，可搭建方块，中心顶部接入机械动力旋转
4. 扳手右键安装座或转向架切换制动；潜行扳手拆卸，或创造破坏任一组件拆除整副；生存用镐拆除并返还转向架物品
5. 允许拿转向架右键已有物理车体底部安装，安装位置必须对准附近轨道
6. 可以把多个顶部安装座所属车体粘合，转向架下部各自保持独立；不要把下部转向架也粘进车体
7. 此原型尚未实现扳手选中后重新放轨；失去轨道导向后请拆除重放

## 运动模型

每副独立安装时只有两个物理体：可扩展的上部车体安装座、下部转向架。共用车体时为一个车体加 N 个转向架
每个转向架通过两个轨道采样点与静态世界建立导向关节，沿轨道方向自由，不直接修改前进位置或速度
枢轴固定竖向支承和侧倾，偏航只加纯阻尼；单副固定俯仰，共用车体多副时允许有限俯仰以通过坡道接续
动力按目标速度误差施加有上限的牵引冲量，不模拟独立旋转轮体，轮子显示调用 Create 的标准转向架渲染 API
输入为零滑行，独立服务制动；固定动力下，载重增大后加速变慢
轨道缺失或导向点超出可捕获范围时解除导向；第一阶段不启用超速脱轨规则

默认满输入 256 RPM 的目标为 12.8 格/秒，每 RPM 对应 0.05 格/秒
最大加速度 2.5 格/秒²，最大制动减速度 4 格/秒²，单副最大牵引力 abs(RPM)×6
共用车体的载重按已注册转向架数平均分摊；应力系数为单副承担质量 / 32，Create 再乘输入转速计算应力负载
本地开发客户端的实际参数文件为 run/config/guidedrailways-server.toml

## 验证

离线构建：gradlew.bat build --offline
客户端：gradlew.bat runClient --offline
279 项动力控制断言通过；这些只验证控制公式，不代表实际行驶已通过
不启动专用服务器或自动驾驶试验，行驶效果由用户客户端观测

测试场景：直轨静止、32/64/256 RPM 正反向起步、断电滑行、扳手制动、左右弯转直线、上下坡、同一车体两个转向架、加铁块载重、保存重进、拆卸保留车体
日志：[GuidedBogie] 给出实际速度、目标速度、输入、承担质量、制动、车体 UUID 和安装座数；[GuideReleased] 记录导向释放
当前尚未进行用户客户端行驶验证，尤其需要确认约束接续、安装高度与多人/粘合后的生命周期

- 新增 829 项纯几何断言，覆盖 R4/R16/R64/R256 曲线入口、中段、出口、反向参数化、坡道及有限轨道端点；原 279 项动力控制检查仍通过
- 用户日志中车辆在弯道附近释放导向后继续直行；新日志附带前后轨道边、参数、曲线标记、误差、朝向对齐度和关节有效性，后续用来验证实际过弯
- 修复最后一个安装座被拆除后再次对已移除刚体调用 onStatsChanged 的异常
- 修复解除导向后速度日志停留在旧值的问题

本轮客户端场景：重新放置一副；32/64 RPM 正反向左右弯；弯转直线；256 RPM；拆除空安装座。尚待用户实际驾驶观测。

## 0.1.2 提速与平台稳定

- 用户测试记录显示 256 RPM 的实际速度约 9.7～9.8 格/秒，接近旧目标 10.24；默认速度比例由 0.04 提高至 0.05，满输入目标 12.8，开发客户端已有配置同步更新
- 原竖向弹簧和侧倾弹簧改为稳定支承，避免空平台的弹性自由度；偏航保持自由角度，仅增加相对角速度阻尼，无偏航回正弹簧
- 单副支承锁定俯仰；同车体多副支承开放 ±0.35 rad 俯仰并增加纯阻尼；安装数量变化时自动重建枢轴
- 新增 pivot 日志：连接点误差、上下结构相对倾角、偏航/俯仰/侧倾相对角速度及支承模式
- 加速度、制动、牵引力预算和应力系数不变；279 项控制与 829 项几何断言通过

本轮客户端场景：空平台静止、直线加速、左右弯、制动和断电滑行；再验证同车体两副及坡道接续。关注小平台是否仍跳动/侧倾/左右摆动，以及实际速度。物理关节稳定性需由客户端测试确认。

## 0.1.3 轮轨视觉对齐与基础开销整理

- 从 Create bogey_wheel.obj 的踏面外圈测得最大半径 0.41934685 格，从 z_ortho.json 测得轨顶高度 5.54375/16 格
- 按标准渲染器轴高 0.75、局部渲染偏移 -0.5 计算车架基准高度 1.015831225（旧值 0.75）；整副转向架和顶部安装座一起抬高，避免只抬模型造成平台穿插
- 轮子动画的滚动半径同步校准；存档重进后使用新导向锚点，不需要删除旧实体，但首次恢复可能发生短暂高度调整
- 直轨跳过原来 18 次没有意义的三分搜索，减少每个导向点每次更新 36 次位置求值
- 轨道图仍每 10 ticks 检查拓扑；轨道边对象未变时复用路径和空间索引，只有新增/删除/替换边时重建空间索引
- 没有转向架时不主动刷新轨网索引；详细关节诊断默认关闭，基本速度记录保留
- 新增 performanceLogging（默认关闭），记录 Java 导向更新均值、峰值、查询数及索引重建次数；测试客户端临时开启。它不包含 Sable 原生约束求解、其他模组或客户端渲染，不能当作完整 TPS/FPS 基准

每副独立装置为 2 个刚体、3 个关节；N 副共用同一车体为 N+1 个刚体、3N 个关节（不含附加机械或其他物理结构）。没有分配轮体、接触式轨道分段或轮缘碰撞。轨网拓扑检查仍与全网边数相关，客户端标准转向架使用普通 BER 渲染，尚未做大量车辆压力测试，不能保证任意数量车辆的性能。

本轮客户端测试：查看静止与轮子转动时踏面是否仍切入轨面，直轨/左右弯/坡道，顶部平台是否仍对齐；用户继续反馈行驶观测，结合 GuidedPerf 测量判断性能。构建及原有 1108 项控制/几何断言通过，资源高度另按实际模型数据核对。

## 0.1.4 碰撞范围与模型对齐

- 原型原来用单个 1.75×0.5×2.4 格碰撞盒，未覆盖完整车架、车轮、轴端；相向碰撞会先穿入外伸模型
- 改为固定的复合碰撞形状：车架主要构件、前后轮组及轴端，共 16 个逻辑盒，统一使用渲染偏移和车架缩放；实际原生盒数由 VoxelShape 合并/切分后决定，启动时 BogieCollision 日志记录
- 前后轮缘旋转包络长约 2.973994 格，轴端总宽 2.375 格；车架顶部、下部轮缘与前后端都纳入碰撞范围
- 轮子盒采用静态旋转包络，不随轮子动画重建，也不添加独立物理体或原生补丁；仍为一个车体加每副一个转向架刚体
- 19147 项资源几何断言读取实际 Create 模型，检查车架全部顶点、前后轮组 64 个转动相位的顶点都在简化碰撞范围内，并检查底部高于原版轨道 2/16 格物理碰撞面；原有 1108 项控制及路径检查仍通过
- 碰撞是简化盒体近似，不是逐三角网格，细小孔洞和曲面边缘存在保守包络；需要用户验证实际碰撞接触位置

客户端场景：两副在直轨上低速正面相撞、侧面相撞、斜向轻碰；观察轮缘、端部和上部是否仍明显穿过，再检查过弯是否受影响。旧存档已穿插的两副请先拉开。未运行专用服务器或自动驾驶。

## 0.1.5 完整碰撞占位与踏面接触高度

0.1.4 的模型外轮廓检查没有覆盖 Sable 默认烘焙器的逐方块裁剪。RapierVoxelColliderBakery 会把每个碰撞盒坐标裁到 [0,1]，因此仅把中心方块的 VoxelShape 扩大并不能实现完整碰撞。这是该版本碰撞仍过晚的明确缺陷。

- 按 Create bogey_frame.obj 的连通网格构件分解，去重后 21 个车架构件，加上前后轮组和轴端包络，共 27 个逻辑碰撞盒
- 将每个盒与所在方块逐格相交，使用中心实体块及相邻隐藏碰撞块，各块的局部坐标均在 [0,1]；运行日志记录实际占用格数及合并后的碰撞盒数
- 所有碰撞块在同一个转向架 SubLevel 内，零额外刚体、零额外关节；隐藏块无方块实体、无独立轮子渲染，质量为 0，原转向架质量保持 80
- 已有转向架载入时自动补齐碰撞占位；若占位处已有玩家方块，不覆盖这些方块，也不会强行启动该副导向
- 模型八角踏面在转动时的支承高度约 0.387426～0.41934685 格。原先按最大外接半径定高会产生约 0.032 格可见空隙；改用最小踏面接触高度，避免悬空，轮缘允许正常伸到轨顶以下，八角边缘存在轻微保守嵌入
- 改为 19228 项资源/裁剪检查：车架顶点和前后轮组 64 相位顶点都必须落在逐格裁剪后的形状内，所有格内盒不得越出 [0,1]；原 1108 项动力/轨道检查仍通过

整体是构件盒与轮组旋转包络的近似，不是逐三角碰撞。原生逐格接触效果需客户端实际验证；未运行专用服务器或自动驾驶。

本轮场景：拉开旧存档中已经穿插的两副，直轨低速正碰、侧碰、斜向碰撞；查看端部、车轮和轴端是否仍明显穿过；观察轮子静止/转动、直轨/弯轨/坡道贴合，最后确认转弯没有卡住。
